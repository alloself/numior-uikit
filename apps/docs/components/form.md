# Form

`@numior/forms` собирает формы из контролов кита. `useForm` держит значения, ошибки и отправку,
`NuiForm` рендерит `<form>` с блоком ошибок и кнопкой, а `NuiFormField` связывает поле с
контролом. Проверку задаёт схема Zod, Valibot или ArkType либо правила пакета.

<Example name="form/Schema" />

## Установка

```ts
import { NuiForm, NuiFormField, useForm } from '@numior/forms';
import '@numior/forms/styles/form.css';
```

## Примеры

### Правила без схемы

`rules` поля — список правил пакета: `required`, `min`, `max`, `email`, `pattern`, `custom`.
Ошибка сервера бросается как `NuiFormError` и живёт, пока значение поля не изменится.

<Example name="form/Rules" />

### Асинхронная проверка

`customAsync` запускается после синхронных правил: после изменения — через `debounce`, при
отправке — с ожиданием ответа. Пока проверка идёт, слот поля получает `pending`.

<Example name="form/Async" />

### Повторяемые группы

`NuiFieldArray` рендерит строки-карточки: `min` прячет удаление, `max` выключает добавление,
`reorderable` добавляет перестановку мышью и с клавиатуры.

## Валидация

`schema` принимает любую схему Standard Schema v1. Issue схемы приходит в поле на своём пути,
issue без пути — в блок ошибок формы. Вывод схемы без единого issue попадает в `onSubmit` как
`output`.

Правила формы задаются в `useForm({ rules })` по пути или шаблону с `*` вместо индекса строки,
правила поля — в `rules` у `NuiFormField`.

По умолчанию форма молчит до первой отправки, после неё каждое изменение перепроверяет поле.
`validateOn="blur"` или `"change"` на форме или поле начинает проверку раньше. Правило,
которому нужны соседние значения, берёт их из контекста: `custom((value, { values }) => …)`.

## Отправка

`NuiForm` рендерит `<form novalidate>`: Enter в поле и кнопка отправляют форму, браузер не
показывает свои подсказки. `onSubmit(values, helpers)` получает значения без скрытых полей и
`output`, `signal`, `setErrors`, `setFormErrors`, `resetForm`. Пока обработчик работает, форма
помечена `aria-busy`, кнопка держит фокус и ширину, повторная отправка игнорируется.

После неудачной отправки фокус идёт на первое невалидное поле. `form.submit()` возвращает
`{ status, invalid, formErrors }`; кнопка `type="reset"` и `resetForm()` сбрасывают форму.

## Скрытые и отключённые поля

Поле, которое не отрендерено, выпадает из проверки и отправки, но значение хранит;
`keepValue="false"` очищает его при скрытии. Отключённое поле отправляется, но не
проверяется. Черновики контролов — число, время, текст комбобокса — `NuiFormField`
подтверждает перед отправкой.

## Хранилище

Значения, состояние полей и ключи строк держит движок пакета. Своё хранилище, например в
Pinia, подключается через `useForm({ engine })` фабрикой типа `FormEngineFactory`; проверки,
отправка и фокус при любом движке остаются за `@numior/forms`.

## Доступность

Ошибки связаны с контролом через `aria-describedby` и `aria-invalid`; блок ошибок формы —
`role="alert"`, который пересоздаётся на каждой попытке. В группах добавление, удаление и
перестановка объявляются в live-регионе, а фокус переходит в новую строку.
