# Form

Пакет `@numior/forms` собирает форму из полей ввода Numior UI: хранит значения, проверяет их и отправляет.
Форму создаёт `useForm`, на странице её выводит `NuiForm` с кнопкой отправки, а каждый контрол
подключается через `NuiFormField`.

<Example name="form/Schema" />

Правила проверки можно описать схемой Zod, Valibot или ArkType, как в примере, или правилами из
самого пакета.

## Установка

```ts
import { NuiForm, NuiFormField, useForm } from '@numior/forms';
import '@numior/forms/styles/form.css';
```

## Примеры

### Правила без схемы

Передайте полю `rules` — список правил из пакета: `required`, `min`, `max`, `email`, `pattern`
или `custom`. Ошибку сервера, например «Этот адрес уже зарегистрирован», бросьте из `onSubmit`
как `NuiFormError`. Она висит под полем, пока пользователь не изменит значение.

<Example name="form/Rules" />

### Асинхронная проверка

Правило `customAsync` проверяет значение на сервере, например свободен ли логин. Оно запускается
после обычных правил: при вводе — через 300 мс после последнего изменения, при отправке — сразу,
и форма ждёт ответа. Пока ответа нет, слот поля получает `pending`.

<Example name="form/Async" />

### Повторяемые группы

`NuiFieldArray` выводит список одинаковых карточек, например гостей. Когда карточек осталось
`min`, кнопка удаления пропадает, а при `max` выключается кнопка добавления. `reorderable`
разрешает переставлять карточки мышью и с клавиатуры.

## Проверка

Свойство `schema` принимает любую схему стандарта Standard Schema v1. Ошибка схемы с путём
показывается под своим полем, ошибка без пути — в блоке над полями формы. Если ошибок нет, результат
схемы приходит в `onSubmit` как `output`.

Правила для всей формы задайте в `useForm({ rules })` по пути к полю. Вместо номера строки в
повторяемой группе пишите `*`: правило применится к каждой строке. Правила одного поля задаются в
`rules` у `NuiFormField`.

До первой отправки форма ошибок не показывает, после неё поле проверяется при каждом изменении.
`validateOn="blur"` или `validateOn="change"` на форме или поле включает проверку раньше. Значения
соседних полей правило получает вторым аргументом: `custom((value, { values }) => …)`.

## Отправка

Форма отправляется кнопкой или клавишей Enter в поле, подсказки браузера не появляются.
`onSubmit(values, helpers)` получает значения без скрытых полей, а в `helpers` — `output`,
`signal`, `setErrors`, `setFormErrors` и `resetForm`.

Пока `onSubmit` выполняется, кнопка показывает загрузку и сохраняет ширину и фокус, а повторное
нажатие ничего не делает. Если проверка не прошла, фокус переходит в первое поле с ошибкой.

`form.submit()` отправляет форму из кода и возвращает `{ status, invalid, formErrors }`. Кнопка с
`type="reset"` и вызов `resetForm()` возвращают начальные значения.

## Скрытые и отключённые поля

Поле, которое сейчас не выведено на странице, не проверяется и не отправляется, но своё значение
помнит. С `:keep-value="false"` значение стирается, как только поле скрывается. Отключённое поле
отправляется без проверки.

Недописанный ввод в контролах — число, время, текст комбобокса — `NuiFormField` подтверждает
перед отправкой, так что в форму попадает то, что видит пользователь.

Поле или форма с `readonly` показывает значение, его можно выделить и скопировать, но не изменить.
Такое поле отправляется без проверки, а кнопка отправки у формы только для чтения выключена.

## Хранилище

По умолчанию значения хранит сам пакет. Чтобы держать их в своём хранилище, например в Pinia,
передайте в `useForm({ engine })` фабрику типа `FormEngineFactory`. Проверка, отправка и перевод
фокуса работают так же при любом хранилище.

## Доступность

Экранный диктор читает ошибку вместе с полем и сообщает, что значение неверно. Ошибки всей формы
он объявляет сразу при каждой неудачной отправке.

В повторяемой группе добавление, удаление и перестановка карточек тоже объявляются вслух, а фокус
переходит в новую карточку.
