# Form

Форма, которая проверяет значения и отправляет их.

<Example name="form/Schema" />

Форма собирается из трёх частей:

- `useForm` создаёт форму: начальные значения, проверку и обработчик `onSubmit`;
- `NuiForm` выводит её с кнопкой отправки и блоком ошибок над полями;
- `NuiFormField` подключает поле: отдаёт контролу значение через `v-bind="field"` и показывает
  подпись и ошибку.

Проверку описывает схема Zod, Valibot или ArkType, как в примере, или правила из пакета.

## Установка

```ts install
import { NuiFieldArray, NuiForm, NuiFormField, useForm } from '@numior/forms';
```

## Примеры

### Проверить без схемы

Передайте полю `rules`.

<Example name="form/Rules" />

В пакете есть правила `required`, `min`, `max`, `email`, `pattern` и `custom`. Ошибку сервера
бросьте из `onSubmit` как `NuiFormError`: она останется под полем, пока значение не изменят.
Текст из второго аргумента `NuiFormError` появится в блоке над полями.

### Проверить на сервере

Добавьте правило `customAsync`.

<Example name="form/Async" />

Правило запускается, когда обычные правила поля уже прошли. При вводе оно ждёт 300 мс после
последнего изменения, при отправке запускается сразу, и форма ждёт ответа. Пока ответа нет, слот
поля получает `pending`.

### Повторить группу полей

Выведите строки в `NuiFieldArray`.

<Example name="form/Lines" />

Когда строк осталось `min`, кнопки удаления пропадают. На `max` кнопка добавления отключается, а
рядом появляется «Достигнут предел строк: 5». С `reorderable` строки переставляют мышью и с
клавиатуры.

Каждая строка — группа с именем «Строка 2», своё имя задаёт `rowLabel`. Ошибка с путём к строке,
например `lines.1`, показывается под ней и читается при входе в строку. После неудачной отправки
фокус встаёт в первое поле такой строки.

## Проверка

`useForm` принимает в `schema` любую схему стандарта Standard Schema v1. Ошибка схемы с путём
показывается под своим полем, ошибка без пути — в блоке над полями. Если ошибок нет, результат
схемы приходит в `onSubmit` как `output`.

Правила для всей формы задайте в `useForm({ rules })` по пути к полю. Вместо номера строки в
повторяемой группе пишите `*`: правило для `'lines.*.quantity'` проверит каждую строку. Правила
одного поля задаются в `rules` у `NuiFormField`.

До первой отправки форма ошибок не показывает, после неё поле проверяется при каждом изменении.
Чтобы проверять раньше, задайте `validateOn: 'blur'` или `'change'` в `useForm` или `validate-on`
у поля. Значения соседних полей правило получает вторым аргументом:
`custom((value, { values }) => …)`.

## Отправка

Форму отправляет кнопка или Enter в поле, встроенные подсказки браузера о проверке не
появляются. `onSubmit(values, helpers)` получает значения без скрытых полей. В `helpers` приходят
`output`, `signal`, `setErrors`, `setFieldError`, `setFormErrors` и `resetForm`.

Пока `onSubmit` выполняется, кнопка показывает индикатор загрузки и сохраняет ширину и фокус, а
повторное нажатие ничего не делает. Если проверка не прошла, фокус переходит в первое поле с
ошибкой, а если ошибка только у формы — на блок над полями.

`form.submit()` отправляет форму из кода и возвращает `{ status, invalid, formErrors }`:

| `status`    | Когда                                                     |
| ----------- | --------------------------------------------------------- |
| `submitted` | `onSubmit` завершился без ошибок                          |
| `invalid`   | проверка не прошла, `onSubmit` не вызван                  |
| `rejected`  | `onSubmit` бросил `NuiFormError` или вызвал `setErrors`   |
| `ignored`   | форма уже отправляется                                    |
| `aborted`   | форму сбросили, пока она отправлялась, и `signal` отменён |

После успешной отправки текущие значения становятся начальными, и форма больше не считается
изменённой. Чтобы взять за начальные ответ сервера, вызовите в `onSubmit`
`helpers.resetForm({ values })`: отправка всё равно завершится статусом `submitted`.

Кнопка с `type="reset"` и вызов `resetForm()` возвращают начальные значения.

## Скрытые и отключённые поля

Поле, которого сейчас нет на странице, не проверяется и не отправляется, но помнит своё значение.
С `:keep-value="false"` значение стирается, как только поле скрывается. Значения, для которых поля
не было вовсе, например `id`, уходят в `onSubmit` как есть.

Перед отправкой `NuiFormField` подтверждает недописанный ввод: число, время, текст комбобокса.
Так в форму попадает то, что видит пользователь.

Отключённое поле отправляется без проверки. Поле с `readonly` показывает значение, его можно
выделить и скопировать, но не изменить, и оно тоже уходит без проверки. У формы с `readonly`
кнопка отправки отключена.

## Хранилище

По умолчанию значения хранит сам пакет. Чтобы держать их в своём хранилище, например в Pinia,
передайте в `useForm({ engine })` фабрику типа `FormEngineFactory`. Проверка, отправка и перевод
фокуса работают одинаково при любом хранилище.

## Доступность

Экранный диктор читает ошибку вместе с полем и сообщает, что значение неверно. Ошибки всей формы
он объявляет при каждой неудачной отправке.

В повторяемой группе диктор объявляет добавление, удаление и перестановку строк. Новая строка
получает фокус, а после удаления фокус переходит на соседнюю строку или на кнопку добавления.

Строку переставляют с клавиатуры ручкой в начале строки. Если фокус уйдёт с ручки, перестановка
отменится.

| Клавиша                | Действие                                           |
| ---------------------- | -------------------------------------------------- |
| Enter или Space        | Взять строку, повторное нажатие ставит её на место |
| Стрелка вверх или вниз | Передвинуть взятую строку                          |
| Escape                 | Отменить перестановку                              |
