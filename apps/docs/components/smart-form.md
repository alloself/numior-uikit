# Smart form

`NuiSmartForm` строит форму по описанию полей, без разметки для каждого поля. Берите её для
типовых форм вроде профиля, настроек или фильтров, а также для форм, которые приходят с сервера в
JSON.

<Example name="smart-form/Profile" />

Поля описывает `formConfig<Values>()`: любые поля ввода Numior, секции, поля по условию,
повторяемые группы и шаги. Проверку и отправку ведёт та же `useForm`, что и в
[обычной форме](/components/form).

## Установка

```ts
import { NuiSmartForm, formConfig, useForm } from '@numior/forms';
import '@numior/forms/styles/form.css';
import '@numior/forms/styles/field-array.css';
import '@numior/forms/styles/smart-form.css';
```

## Примеры

### Шаги

Передайте `steps` вместо `fields`, и форма станет пошаговой. Перейти дальше можно, только когда
поля текущего шага заполнены без ошибок. Открытый шаг хранится в `v-model:step`, а кнопка на
последнем шаге отправляет форму.

<Example name="smart-form/Wizard" />

### Фильтры в строку

С `inline="fit"` поля встают в одну строку, как фильтры над таблицей. Если места не хватает,
поля переносятся на следующую строку; с `inline="grow"` поля растягиваются на всю ширину.

## Конфигурация

Поле описывает `field(Component, (v) => v.email, options)`: компонент, функция, которая выбирает
значение из модели формы, и настройки. В настройках задаются `label`, `description`,
`required`, `rules`, `props` компонента, `when` и `area`.

TypeScript выводит тип значения из функции выбора и сверяет его с моделью компонента. Если
компонент хранит значение не в `v-model`, а в именованной модели, укажите её: `model: 'values'`.

`section({ title, layout, fields })` выводит группу полей под общим заголовком.
`array((v) => v.contacts, { newRow, fields })` выводит повторяемую группу, например список
контактов, а поля одной строки описывает отдельный `formConfig<Row>()`.

## Условия и раскладка

Поле, секция или группа видны, пока их `when(values, row)` возвращает `true`. Скрытое поле не
проверяется и не отправляется, но его значение сохраняется и вернётся, когда поле появится снова.

`layout` записывается как CSS-свойство `grid-template-areas`, а имена областей — это пути полей
или их `area`. Если форма уже `36rem`, поля встают в одну колонку, поэтому одна форма подходит и
для диалога, и для телефона.

## Из JSON

`parseFormConfig(json, { controls })` собирает конфигурацию из JSON. Поле в JSON задают
строковый `type` из реестра компонентов, путь `name`, `props`, условие `when` и правила
`required`, `min`, `max`, `email`, `pattern`.

`props` проверяет сам компонент из реестра. Если тип неизвестен, `props` не прошли проверку или
запись не разобрать, вместо формы вернётся список `issues` с кодом ошибки и путём до неё.

Правило `pattern`, чей `source` — не регулярное выражение, тоже попадает в `issues`. Путь ведёт
до самого правила, например `fields.0.rules.1`.

`formConfig({ controls }).control('select', (v) => v.country, { props })` берёт компонент из
реестра по ключу, и TypeScript знает типы его `props`. Значения полей из JSON имеют тип
`unknown`, потому что их форму определяет присланная конфигурация. Подробнее — в
[useControls](/composables/controls).

## Слоты

Слот с именем, равным пути поля, задаёт содержимое компонента, например радиокнопки группы или
подпись флажка. В слот приходят `error`, `invalid`, `touched` и `pending`, а в повторяемой группе
ещё и `row`.

Слот `actions` заменяет кнопки формы. В него приходят `submit`, `reset`, `pending`, `dirty` и
данные о шагах.
