# Валидация форм

Как проверять значения формы схемой или правилами и показывать ошибки с сервера.

<Example name="form/Schema" />

Форма из `@numior/kit/forms` проверяет значения схемой Standard Schema (zod, valibot, arktype),
правилами для полей или тем и другим сразу. До первой отправки форма не показывает ошибок.
Компоненты форм описаны на страницах [Form](/components/form) и [Smart form](/components/smart-form).

## Схема

Передайте схему в `useForm({ schema })`. Подходит любая схема Standard Schema v1, адаптер не
нужен.

Ошибка с путём выводится у своего поля, ошибка без пути — в блоке ошибок формы. Если ошибок
нет, `onSubmit` получает результат схемы в `output`, уже с типом схемы.

## Правила

Используйте правила, если схемы нет или проверка зависит от других полей. Встроенные правила:
`required`, `email`, `min`, `max`, `pattern` и `custom`.

<Example name="form/Rules" />

```ts
const form = useForm({
  initialValues: { password: '', confirm: '' },
  rules: {
    password: [required(), min(8)],
    confirm: [custom((value, { values }) => value === values.password || 'Пароли не совпадают')],
  },
});
```

Чтобы заменить текст ошибки, передайте правилу `{ message }`. Тексты по умолчанию лежат в
словаре `formRules`.

Правила формы задаются по пути поля. Для строк списка пишите `*` вместо индекса:
`'lines.*.quantity'`. Правила одного поля можно передать и в свойство `rules` у `NuiFormField`.

Чтобы проверить значение без формы, вызовите `runRules(rules, value, context)`. Функция вернёт
текст первой ошибки или `undefined`. Так таблица проверяет правку ячейки теми же правилами.

## Асинхронная проверка

Для проверки на сервере используйте `customAsync`: функция получает значение и `signal`. Пока
пользователь печатает, предыдущий запрос отменяется, а поле показывает, что идёт проверка.

Если проверка завершилась исключением, поле считается непроверенным и показывает «Не удалось
проверить значение». Отправка формы блокируется, а следующая отправка или уход из поля повторяют
запрос. Само исключение получает `onCheckError(error, path)` в настройках `useForm`.

Проверка читает соседние поля через `values`. Если такое поле изменилось, пока шёл запрос, ответ
отбрасывается и запрос повторяется. `form.validate({ silent: true })` тоже ждёт асинхронные
проверки, но ошибок не показывает.

## Когда проверять

Когда проверять значение, задаёт `validateOn` в `useForm` или `validate-on` у поля:

- `submit` — при отправке формы, по умолчанию;
- `blur` — когда поле теряет фокус;
- `change` — при каждом изменении.

После первой отправки поле перепроверяется при каждом изменении, какой бы режим ни был выбран.

## Ошибки сервера

Чтобы показать ошибки с сервера, бросьте в `onSubmit` исключение
`NuiFormError({ email: 'Адрес занят' })` или вызовите `setErrors`:

```ts
onSubmit: async (values, { setErrors }) => {
  const response = await api.register(values);

  if (response.status === 422) {
    setErrors(response.errors);
  }
};
```

Ошибки полей выводятся у полей, ошибки формы — в блоке с `role="alert"`. Фокус переходит на
первое поле с ошибкой.
