---
title: "Ядро форм на собственном движке со сменным хранилищем"
status: accepted
date: 2026-09-26
---

## Context

План 1.0 включает пакет форм: ручные формы и формы из конфигурации с общим состоянием.
Интервью 2026-09-25 выбрало основой vee-validate 5, референсом — контракт и боли `LnSmartForm`
(код не переносится), валидацию — Standard Schema плюс встроенные правила, решило, что форма
владеет отправкой, скрытые поля выпадают из проверки и отправки, а ошибки не показываются до
первой попытки отправки. Новейшая ветка 5.x — `5.0.0-beta.1` (2026-03-04), стабильной 5.x нет,
`latest` — 4.15.1.

Разбор исходников беты показал, что оркестрация схемы в vee-validate не подходит этим решениям:
каждая проверка прогоняет всю схему через таймер 5 мс и применяет только последний прогон;
фоновые «тихие» прогоны идут на монтирование, размонтирование, сброс и мутации массивов; сырые
результаты приходят в точечных путях, а состояние полей хранится в скобочных; issue на пути без
поля поднимается к полю по голому `startsWith` (`name` ловит `nameSuffix`) или молча блокирует
`handleSubmit`; правила поля игнорируются при схеме формы; без схемы `handleSubmit` и
`validate()` проходят через валидаторы полей и затирают их ошибки.

Поэтому слой форм с первого коммита сам проверял, отправлял и сбрасывал, а от vee-validate брал
только хранилище значений, состояние полей и ключи строк — через приватные внутренности беты.
Ревью 2026-09-26 признало это лишним: ради хранилища пакет тянул бету с точным пином, которая
блокирует релиз, и 10 KB gzip сверх собственного слоя. Решение: собственный движок по умолчанию,
а vee-validate остался на день необязательным движком. Разбор 2026-09-28 («зачем своё ядро,
если есть vee-validate») закрепил: поведение важнее объёма своего кода, адаптер удалён, сменное
хранилище через `FormEngineFactory` остаётся.

## Decision

- `@numior/forms` зависит только от `@numior/primitives` (словарь текстов правил) и
  `@numior/vue`; сторонних движков форм в зависимостях и peer нет. Снимки значений делает
  собственная копия: простые объекты, массивы, даты и `Map` копируются вглубь, члены `Set`,
  экземпляры классов, файлы и функции переходят по ссылке; копия сверяется с оригиналом через
  `isEqualValue`, и только эта проверка сужает её тип до типа оригинала, без приведения.
  Сравнение: дата без времени равна такой же, запись без прототипа равна обычной с теми же
  ключами, `URL` сравнивается по `href`, `RegExp` — по образцу и флагам; экземпляр класса без
  собственных перечислимых полей (состояние в приватных полях или слотах) равен только самому себе.
- `FormEngine` — хранилище значений (`raw: V`, реактивное представление `values: V`, счётчик
  записей `version` и типизированный `snapshot()`), состояние поля (`touched`, попытка, ошибки,
  `pending`), ключи строк повторяемых групп, сброс и счётчик попыток. Значения движок не
  читает за поле: поле получает только своё состояние, массив — только ключи строк. По умолчанию работает собственный движок `engine/form-engine.ts`:
  reactive-хранилище поверх копии начальных значений, состояние поля живёт на экземпляре поля и
  идёт за ним при смене пути, сброс очищает состояние живых полей. Ключи строк не меняются при
  вставке, удалении, перестановке и обмене; внешняя запись всего массива добирает или отрезает
  ключи по длине. `useForm({ engine })` принимает другую фабрику `FormEngineFactory`; типы движка
  публичны, поэтому своё хранилище (например, в Pinia) подключается так же.
- Адаптер vee-validate (`@numior/forms/vee-validate`, 2026-09-26 … 2026-09-28) удалён: он
  держался на приватных полях беты `5.0.0-beta.1`, требовал второй набор контрактных тестов и
  prerelease-peer, а потребителей у него не было. Своё хранилище (Pinia, стороннее состояние)
  подключается через `useForm({ engine })` фабрикой `FormEngineFactory`; контракт движка
  закрепляет `engine-contract.test.ts` на собственном хранилище.
- Поля читают значения селекторами: `useField((v) => v.contacts[0]?.name, { form })`,
  `NuiFormField :name`, `NuiFieldArray :name` и конфигурация умной формы. Тип значения выводит
  TypeScript из тела селектора, поэтому значение, правила и привязка типизированы без приведения.
  Путь поля записывается вызовом селектора на прокси: читать можно одну цепочку свойств через
  индексы и `?.`; ветвление, вызов метода или чтение самих значений бросают ошибку. Каждое
  чтение сверяет результат селектора со значением по записанному пути (`Object.is`), поэтому
  подмена вида `v.nickname ?? v.name` не читает молча другое поле. Типизированное реактивное
  чтение даёт `reactiveView(raw)`: прокси с типом `V`, который пересылает чтение и запись
  реактивному объекту Vue; для значений без `ref` внутри его чтения совпадают с чтениями `raw`,
  а зависимость отслеживается ровно по прочитанному пути. Строковый путь без типа даёт
  `byPath(path)` со значением `unknown`. Типизированное чтение по строке (`readAt`) удалено.
- Форма передаётся полям явно (`form` обязателен): тип значений не проходит через inject.
  `provideForm` и `useFormContext` работают с `FormHandle` — контекстом без значений и без
  хоста. Хост формы живёт в поле `[FORM_HOST]` контекста, а не в WeakMap, и типизирован по `V`.
  Записи реестра, хост, валидация и асинхронные проверки обобщены по `V`; модули, которые только
  передают записи дальше, принимают `Entry<never>`: это надёжный верхний тип — `check` у него
  вызвать нельзя, а расширение не опирается на бивариантность методов.
- Конфигурация умной формы: `field(Component, (v) => v.email, options)` и
  `array((v) => v.contacts, options)`; селектор стоит перед правилами, чтобы TypeScript вывел тип
  значения до `custom((value) => …)`. Правила поля оборачиваются в правила значений формы, которые
  читают значение тем же селектором; поля строки поднимаются до значений формы по индексу строки
  через геттер её метаданных, так что `when`, `props` и правила получают типизированную строку,
  а исчезнувшая строка просто пропускает условие и правило. Тип поля сверяется с контролом:
  `R` должен подходить модели (`modelValue`, у необязательного пропа — вместе с `undefined`), а
  значение `update:modelValue` — полю. У обобщённых контролов (`NuiSelect<T>`) модель из типа
  компонента выводится как `unknown`, и проверка события для них пропускается: их тип задаёт
  место использования. Слоты полей — содержимое контрола (радиокнопки группы, подпись чекбокса)
  без значения и привязки; свой контрол целиком передаётся в `field()` компонентом.
- Наш слой: реестр активных путей, прогон проверки (схема пользователя, правила формы по
  шаблону `items.*.name`, правила поля, серверные и ручные ошибки), маршрутизация issue,
  политика времени, отправка, сброс с эпохой, dirty по собственному снимку, фокус и запросы по
  префиксу. Синхронная схема и синхронные правила применяются в том же обработчике, что и
  запись значения, — одно действие, один рендер; асинхронная схема применяется при разрешении,
  побеждает последний начатый прогон.
- Маршрутизация issue: без пути — ошибка формы; ближайшее активное поле или владелец на пути
  или выше него (с границами сегментов) — ему; предок активных полей без своего владельца —
  ошибка формы с путём; остальное отбрасывается и видно в `validate().ignored`, чтобы поле,
  которого пользователь не видит, не блокировало отправку. Серверные ошибки не отбрасываются
  никогда: неизвестный или скрытый путь уходит в ошибки формы вместе с путём.
- Скрытые поля: пути, которые когда-либо регистрировались, но сейчас неактивны или
  размонтированы, вырезаются из копии для схемы и отправки; значение в хранилище остаётся.
  Правила полей получают полный снимок с типом `V`, как асинхронные проверки, `when` и `props`:
  само скрытое поле не проверяется, но правило соседнего поля видит его значение. Иначе
  правило получало бы вырезанную копию под типом `V`, то есть тип врал бы. `keepValue: false`
  удаляет значение при скрытии (ключ объекта удаляется, позиция в массиве сохраняется), поэтому
  его тип — `KeepValue<R>`: `false` разрешён, только если `undefined` входит в тип значения,
  и хранилище не расходится с `V`. Значение, которое не показывало ни одно поле, отправляется как
  есть. Отключённое поле отправляется, но не проверяется.
- Время: `submit` по умолчанию, `blur` и `change` на форме или поле; после попытки каждое
  изменение и уход с поля перепроверяют его; `validate({ paths })` делает попытку только для
  своих путей («Далее» в шагах); ошибки формы видны после полной попытки.
- Правила: `required` (пустыми считаются `undefined`, `null`, строка из пробелов, `[]` и `false`
  — для согласия), `min` и `max` (символы строки по code point, число по значению, длина
  массива), `email`, `pattern`, `custom`; все, кроме `required`, пропускают пустое значение.
  Тексты — пространство имён словаря `formRules` (RU/EN, `messages` и `translate` из конфига),
  явный `message` правила побеждает.
- Асинхронные проверки создаёт отдельная фабрика `customAsync`: рантайм должен знать об
  асинхронности до вызова, поэтому такие правила помечены символом, и простая `async`-функция
  на их место не проходит проверку типов. Проверка стартует, только когда синхронные правила и
  схема не нашли ошибки у поля; после изменения — с задержкой `debounce` (300 мс), после ухода с
  поля — сразу, при отправке и `validate()` — сразу и с ожиданием. Побеждает последний запуск,
  прежние получают `abort()` в `signal`; поле в `pending`, пока проверка идёт; сброс отменяет
  всё и очищает кэш. Ответ кэшируется по значению поля и по значениям, которые проверка
  прочитала из `context.values`: снимок отдаётся ей через прокси, который записывает прочитанные
  листья (контейнер — только если перечислены его ключи или проверено наличие ключа), и ответ
  считается свежим, пока все записанные значения равны текущим. Устаревший ответ не даёт ошибки,
  отправка спрашивает заново, а поле с попыткой перепроверяется через `debounce` после любого
  изменения, которое сделало его ответ устаревшим. Явные `deps` у правила отвергнуты: их легко
  забыть, а запись чтений точна и не требует от автора правила ничего.
- Повторяемые группы (`useFieldArray`): строки с ключами движка, `touched` и ошибки идут за
  строкой вместе с её компонентом; `update` пишет через движок и перепроверяет затронутые поля.
  После вставки, удаления и перестановки перепроверяется только сама группа (правила числа
  строк): пути полей в строках догоняют новые индексы лишь после рендера, и полная раскладка
  ошибок в том же тике приписала бы их чужим строкам. Контейнер, выключенный через `active`,
  выключает все поля внутри себя.
- Отправка: повторный вызов во время отправки возвращает `ignored`; flush-хуки полей →
  проверка эпохи → попытка (счётчик, `touched` и `validated` у всех) → проверка →
  `onSubmit(копия введённых значений, { output, signal, setErrors, setFieldError, setFormErrors,
  resetForm })`. Копия без скрытых полей типизирована `SubmittedValues<V>` — глубокая частичная,
  элементы списков тоже могут быть `undefined`; перед вызовом `isPrunedFrom` сверяет её с полным
  снимком (каждый ключ есть в снимке с тем же значением), поэтому тип подтверждён проверкой, а не
  приведением. `output` — вывод схемы, только если не было ни одного issue. `NuiFormError`
  раскладывается по полям и ошибкам формы и живёт, пока значение поля не изменилось; другие
  ошибки пробрасываются. После успеха снимок становится начальными значениями, правки во время
  ожидания остаются dirty.
- Сброс увеличивает эпоху, отменяет `signal`, сбрасывает хранилище с `force` и состояние
  полей; устаревшие flush и проверки отбрасываются. Документ загружается только через
  `resetForm({ values })`, глубокого наблюдения за `initialValues` нет.
- `NuiForm` рендерит нативный `<form novalidate>`: Enter и клики доходят через `submit`, повторная
  отправка во время ожидания игнорируется, форма получает `aria-busy`, кнопка по умолчанию —
  `NuiButton type="submit" loading` с прежней шириной и фокусом. После неудачи фокус идёт на первое
  невалидное поле в порядке DOM, иначе на блок ошибок формы (`NuiAlert tone="error"`), который
  пересоздаётся на каждой попытке, чтобы экранный диктор объявил его снова. Нативный `reset`
  сбрасывает форму. Продолжение отправки учитывается в `settled()`. `reserveError` у `NuiForm`
  (и у `NuiSmartForm`, который передаёт его в `NuiForm`) идёт через область формы вместе с
  `disabled`: `NuiFormField` берёт свой проп, иначе значение формы, и `NuiField` держит под
  контролом пустую строку высотой в строку ошибки, чтобы появление ошибок после отправки не
  сдвигало форму. `readonly` идёт тем же путём (2026-09-28): `NuiForm`/`NuiSmartForm` →
  область формы → `NuiFormField`/`NuiFieldArray` → контекст поля в primitives → контрол. В
  движке `disabled` и `readonly` записи сливаются в `inert`: такое поле отправляется, но не
  проверяется — ошибку под полем, которое пользователь не может исправить, показывать
  бессмысленно. Контрол в режиме чтения фокусируем, его значение читается и копируется;
  нативные текстовые контролы получают атрибут `readonly`, кастомные (select, чекбокс, радио,
  переключатель) — `aria-readonly` и игнорируют клик, скрытые аффордансы (степперы, шеврон,
  очистка, зона загрузки) схлопываются. Кнопка отправки формы в режиме чтения отключена, а
  `NuiFieldArray` прячет добавление, удаление и грипы.
- Формы из JSON: `parseFormConfig(json, { controls })` (`smart-form/parse-config.ts`) принимает
  список записей `field | section | array`, ищет контролы в реестре `@numior/primitives`
  (см. `controls.adr.md`), прогоняет `props` через гард контрола, строит условия `when` из
  `{ path, equals }`/`{ path, in }` и правила из встроенного набора; результат — либо готовые
  `NuiSmartFormEntry`, либо `issues` с путями. Массивы идут через тот же `array()` строитель и
  `liftEntry`, поэтому строки из JSON ведут себя как строки из кода. Значения полей — `unknown`,
  граница доверия проходит по источнику JSON, а не по форме.
- `NuiFormField` оборачивает `NuiField`: ошибка, `aria-invalid`, `aria-describedby` и отметка
  обязательности идут через существующий контекст поля. `touched` ставится по `focusout` корня
  поля, а не по `blur` контрола: фокус внутри составного контрола (список select, сегменты
  времени) поле не покидает. Слот отдаёт привязку `{ name, modelValue, 'onUpdate:modelValue' }`
  с типом значения из селектора: контрол, который отдаёт значение другого типа, не проходит
  проверку типов. Контролы кита отдают ровно тип своей модели: одиночный и множественный выбор
  разделены (`v-model` и `v-model:values`), чекбокс булев, набор значений — `NuiCheckboxGroup` с
  `v-model:values` (до 2026-11-10 — `v-model`; привязка поля формы к нему — `:values` и `@update:values`).
- `NuiFieldArray` — `fieldset` с подписью и описанием, строки-карточки в `TransitionGroup` по
  ключу строки: поля строки, их `touched` и ошибки идут за ней. Каждая строка регистрирует свой
  путь владельцем, поэтому ошибка уровня строки (`contacts.1`) видна в строке, а ошибка списка —
  под списком. Перестановка на `useReorder`: грип виден при наведении и фокусе (на тач-экранах
  всегда), мышью строку ведёт непрозрачный «призрак» — плашка с номером строки у начала
  списка высотой в контрол, центр которой держится на указателе (`translate: 0 -50%`, зажата в
  пределах списка через `clamp()`, смещение захвата не нужно), линия вставки встаёт в промежуток
  между строками и видна рядом с плашкой (2026-09-27: призрак во всю ширину перекрывал линию и
  висел над указателем); клавиатура — пробел или Enter захватывает и отпускает, стрелки двигают, Escape
  отменяет, каждый шаг объявляется в live-регионе. Грип строки, которую некуда двигать, скрыт с
  сохранением места: прозрачность отключённой кнопки перебивала бы скрытие в покое. `min`
  прячет удаление, `max` выключает добавление с текстом предела. После добавления фокус идёт в
  новую строку, после удаления — в следующую, предыдущую или на кнопку добавления, после
  перестановки — на грип строки.
- `NuiSmartForm` строит форму из конфигурации `formConfig<T>()`: `field(Component, { name, props,
  when, area, rules, … })` сверяет `name` с путями формы, а `props` — с props самого компонента
  (без `modelValue`, `id`, `name`, `invalid`, `required`, `disabled`) и нативными атрибутами;
  `props` может быть функцией значений. Контрол с именованной моделью (`v-model:values` у
  множественных `NuiSelect`, `NuiCombobox`, `NuiList`, `NuiTree`) подключается через `model`:
  тип значения и проверка события берутся из пропа и события этой модели, ячейка привязывает
  именно их, иначе массив уходил бы в `modelValue` одиночного режима и терялся. `section` рендерит `fieldset` с заголовком и своей
  раскладкой, `array` — `NuiFieldArray`, поля строки типизированы по строке, а `when` строки
  получает её значение. `rules` в `field()` типизированы по значению пути и типу конфигурации;
  запись хранит их свободным (bivariant) типом, как `when` и `props`, иначе разнородный список
  записей не собрать. Правилам поля строки ячейка отдаёт в `values` значение строки из
  проверяемой копии, как `when` и `props` видят строку; обёртки сохраняют метку происхождения. `layout` пишется в синтаксисе `grid-template-areas`: DOM идёт в порядке
  чтения макета, строки из одних скрытых полей выпадают, контейнерный запрос (уже 36rem)
  складывает всё в колонку; `inline` и `'grow'` дают строку фильтров. Появление и исчезновение ячеек симметричны
  (2026-09-27, раньше анимировалось только появление, а скрытое поле пропадало разом): уходящая
  ячейка закрепляется на измеренных координатах (`position: absolute`, `inert`) и гаснет, соседи
  переезжают FLIP-переходом `TransitionGroup`, а высота сетки тянется к новой через
  `useBlockSizeTween` из primitives (замер до и после обновления, Web Animations с
  `--transition-duration-normal` и `--ease-nui`, нулевая длительность — без анимации). Пока высота
  тянется, сетка обрезана по движущемуся нижнему краю (`clip-path: inset(-100vmax -100vmax 0)`
  в тех же ключевых кадрах: боковые края не режутся, фокус-кольца у кромок целы), а пока в ней
  есть уходящие ячейки — ещё и правилом `:has(> .nui-smart-form__cell--leaving)`, потому что Vue
  запускает затухание на два кадра позже и уходящая ячейка переживает анимацию высоты: иначе
  появляющиеся и гаснущие поля рисуются поверх следующей секции. `align-content: start` не даёт
  строкам растягиваться, пока сетка выше содержимого, иначе верхние поля съезжали вниз при
  скрытии нижних. Именованную область
  ячейка получает, только если она есть в плане макета, иначе размещается автоматически:
  `grid-area` с именем без шаблона уводит элементы на неявные линии и складывает их друг на
  друга. Разделитель между соседними секциями — нижняя граница предыдущей: легенда `fieldset`
  рисуется на верхней границе, а WebKit не выводит плавающую легенду в сетку. Все поля конфигурации
  регистрируются в ядре заранее, поэтому скрытое через `when` поле выпадает из отправки, даже
  если его ни разу не показывали. Слоты `#[путь]` заменяют контрол, `#[путь]:after` добавляют
  содержимое в ту же ячейку; пути строк пишутся без индекса (`contacts.email`). Слоты доходят до
  ячеек через provide/inject, а не пробросом по рекурсии. `defineSlots` типизирует их по
  значениям: `FormSlotPath` — пути без индексов строк, `FormAfterSlotPath` — их `:after`, плюс
  `actions` и `form-errors`. Пересечение идёт в порядке поля → `:after` → фиксированные слоты,
  потому что vue-tsc берёт параметры слота из последней сигнатуры, а ключи `:after` — условный
  тип: отображённый тип с переименованием ключей не сопоставляется со слотами `h()` при
  дженерике. `v-model:step` принимает `undefined`, чтобы привязываться к необязательному ref
  при `exactOptionalPropertyTypes`.
- Шаги `NuiSmartForm`: `steps` + `v-model:step` + `NuiStepper` над панелями. Все панели
  смонтированы, потому что размонтированное поле выпало бы из проверки, и скрыты атрибутом
  `hidden`: `v-show` применяет `display` в пост-хуке директивы дочернего компонента, уже после
  того как форма фокусирует первое поле нового шага, и фокус не доходил.
  «Далее» — `validate({ paths })` полей шага: при ошибке фокус на первое невалидное поле шага, иначе
  переход и фокус на первое поле следующего. «Назад» и клик по пройденному шагу степпера не
  проверяют. Финальная отправка при ошибке открывает шаг с первым невалидным полем, и `NuiForm`
  фокусирует его. Степпер ставит статус `error` только шагам с видимыми ошибками; live-регион
  объявляет «Шаг 2 из 3: Профиль»; Enter на промежуточном шаге работает как «Далее»; сброс
  возвращает к первому шагу. Панели ищутся через ссылки шаблона, а не по `id` документа.
- Мост черновиков: `useFieldControl(props, { commit })` регистрирует коммит неподтверждённого
  ввода контрола (lazy-текст, число, свой текст комбобокса, зажатие времени) в области, которую
  открывает `NuiFormField` (`provideDraftCommits` в `@numior/primitives`); поле передаёт их ядру
  как flush. Программная отправка (Cmd+S, `requestSubmit()`) не теряет набранное, хотя фокус не
  уходил с контрола.
- Публичные типы собственные (`FormPath` в точечной нотации, `FormPathValue`, Standard Schema
  без зависимости от `@standard-schema/spec`); `test:artifacts` проверяет, что ни базовый UI, ни
  формы не тянут сторонние движки форм. Контрактные тесты `engine-contract.test.ts` закрепляют
  поведение хранилища, на которое опирается ядро. Пакет не держит prerelease-зависимостей,
  поэтому релизный плагин его не блокирует (@.archcore/semantic-release.adr.md).

## Alternatives Considered

- Схема через `validationSchema` vee-validate с нейтрализацией фоновых прогонов счётчиком
  запросов и побочным каналом результатов: таймеры в каждой проверке, два рендера на действие
  и хрупкая зависимость от порядка прогонов.
- vee-validate 4.15.1: без нативного Standard Schema.
- Диапазон `^5.0.0-beta.1`: беты меняют поведение без предупреждения.
- Реэкспорт `Form`, `Field`, `FieldArray` из vee-validate: обходят реестр, их issue стали бы
  «неизвестными».
- `structuredClone` для снимков: падает на функциях и теряет прототипы классов.
- Оставить vee-validate основным хранилищем (так было до ревью 2026-09-26): бета с точным пином
  блокирует релиз, адаптер держится на приватных полях, а 10 KB gzip уходят на хранилище, которое
  собственный движок заменяет двумя сотнями строк.
- Перейти на стабильную vee-validate 4.x и принять её политику (разбор 2026-09-28): ошибки при
  первом blur/change, либо схема, либо правила поля, без Standard Schema в стабильной ветке;
  слой оркестрации на 1,7 тыс. строк всё равно остался бы поверх, а решения интервью пришлось бы
  отменить. Отклонено: поведение важнее объёма своего кода.
- Держать необязательный адаптер vee-validate (2026-09-26 … 2026-09-28): один файл и контрактные
  тесты, но приватные внутренности беты, prerelease-peer и никого, кто им пользуется. Удалён.

## Consequences

Сборка со всеми экспортами ядра (Vue и `@numior/primitives` external, production, минификация
Vite): ядро с собственным движком 23,4 KB / 8,3 KB gzip (с vee-validate было 56,6 KB / 18,6 KB
gzip). Ни базовый UI, ни формы сторонних движков не загружают, это проверяет `test:artifacts`.

Правила поля, `validateOn`, `debounce` и `keepValue` реактивны (`MaybeRefOrGetter`): запись
реестра читает их геттерами, а смена правил сбрасывает кэш асинхронной проверки и, если ошибки
поля уже видны, перепроверяет форму в pre-watcher — тем же рендером. Встроенные правила, `custom`
и `customAsync` помечены происхождением (аргументы фабрики или функция проверки), и списки
сравниваются по этим меткам, поэтому инлайн-массив одних и тех же правил не перепроверяет поле
на каждом рендере; запись ошибок и так пропускает одинаковые.

`compiler-ssr` Vue 3.5 выводит props `TransitionGroup` (классы переходов) атрибутами обёртки; это
безвредно и касается также дерева и списка строк. Значения условных полей в типе формы должны быть
необязательными: в отправку они не попадают. Ключи с точкой в путях не поддерживаются.

## Тексты поля на контроле (2026-09-27)

Каждый контрол поля (`NuiFieldControlProps`: Input, Textarea, Select, Combobox, NumberField,
Switch, Checkbox, CheckboxGroup, RadioGroup, TimeField, DatePicker, DateRangePicker, Upload)
принимает `label`, `description`, `error` и `reserveError`. `useFieldControl` создаёт для
контрола собственный `FieldContext` из этих текстов, когда его не оборачивает `NuiField`
(`own`), и отдаёт `frame` — данные для части `NuiFieldFrame`, которой обёрнут корень
каждого контрола: та же разметка `.nui-field` с подписью, описанием и ошибкой, что у
`NuiField`, и та же aria-проводка (`for`/`id`, `aria-describedby`, `aria-invalid` от ошибки).
У Checkbox и Switch `label` — встроенная подпись рядом с боксом (`inlineLabel`: контекст без
`labelledBy`, рамка только с описанием и ошибкой), у групп рамка — `fieldset` с `legend`.
Внутри внешнего `NuiField` контрол свои тексты не рисует: внешнее поле побеждает. `NuiField`
остаётся для слотов подписи, нескольких контролов в одном поле и `NuiFormField`; части
`NuiFieldLabel`/`NuiFieldDescription`/`NuiFieldError` принимают контекст пропом `field`, а
без него берут его из инъекции. `NuiUpload` перешёл на общий интерфейс (`hint` →
`description`).

Обёртка `.nui-field` у контрола вне `NuiField` рисуется всегда, а не только при наличии
текстов: иначе корень контрола менялся при появлении `error`, и Vue пересоздавал элемент ввода
с потерей фокуса. `NuiFieldFrame` — функция рендера, потому что `<slot>` в шаблоне
компилируется во фрагмент и SFC не может вернуть элемент слота своим корнем (вечер 2026-09-27).

## Асинхронные правила: списки и повторная проверка при отправке (2026-09-28)

Представление значений для асинхронного правила — записывающий Proxy; для одного и того же
пути он отдаёт один и тот же дочерний Proxy, поэтому селектор поля со значением-списком или
объектом (`(v) => v.tags`, массив полей) проходит проверку тождества `readSelected`, а
селектор, читающий другой путь, по-прежнему отклоняется. Отправка ждёт асинхронные
проверки в цикле: если значение поля изменилось, пока его проверка шла, форма проверяет новое
значение заново и только потом отдаёт его в `onSubmit`; устаревший ответ никогда не считается
подтверждением.

## Перестановка строк списка и состояние по пути (2026-11-11)

Часть состояния формы хранится по пути: серверные ошибки (`core.external`), сохранённое состояние
размонтированного поля (`core.retained`), ответ идущей проверки. Строки списка меняют путь при
`insert`, `remove`, `move`, `swap` и `replace`, поэтому каждая такая операция сообщает хосту
перестановку: `host.reshape(path, relocate)`, где `relocate` переводит старый индекс строки в новый
или в `undefined`.

- Серверные ошибки переезжают вместе со строкой и исчезают вместе с удалённой строкой.
- Сохранённое состояние под списком сбрасывается, а поля, размонтированные этой перестановкой,
  ничего не сохраняют и не стирают значение по своему старому пути (до конца ближайшего обновления
  DOM). Новая строка на месте удалённой начинает чистой.
- Проверка, которая шла во время перестановки, не применяется: её ответ посчитан для старого
  порядка. Она запускается заново после обновления DOM (`core.session.shape`).
- `move` и `swap` движка считают перестановку по индексам (`engine/places.ts`): строка без значения
  переезжает как любая другая, позиция вне списка ничего не меняет.

Сохранённое состояние поля, скрытого `v-if`, возвращается только к тому же значению: если значение
изменилось, пока поля не было, поле возвращается чистым. Поле с `keepValue: false` состояние не
сохраняет вовсе — его значение стёрто.

Асинхронное правило, завершившееся исключением, даёт полю сообщение `formRules.unchecked` и
блокирует отправку; следующая проверка поля или отправка повторяют запрос. Исключение получает
`onCheckError` из настроек `useForm`.

Отвергнуто: хранить серверные ошибки по ключу строки (ключи знает только движок, а путь ошибки
приходит с сервера); сравнивать снимок значения при возврате состояния строке (снимок на момент
размонтирования уже принадлежит другой строке).
