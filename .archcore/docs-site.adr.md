## Context

Документация `apps/docs` стояла на теме VitePress по умолчанию: демо жёстко в светлой теме,
74 из 84 блоков кода расходились с демо над ними, таблицы API писались руками, а слоты, события
и CSS описывались абзацами; проза пересказывала внутренности (BEM-элементы, приватные
переменные) и оговорки. Проверял доку только `vitepress build`, поэтому пустые демо проходили
CI. Пользователь назвал такую доку «нейрослопом» и задал планку: уровень ui.shadcn.com и
vuetifyjs.com, весь интерфейс доки — из компонентов и утилит самого kit. Решения согласованы
в интервью 2026-09-26 (план `frolicking-twirling-simon`, 23 решения).

## Decision

- Граница kit: всё, чего доке не хватает, становится полноценной частью kit (unit/SSR/e2e/axe,
  секция playground, страница); `apps/docs` держит только тонкие композиции компонентов и
  утилит — ни одного `<style>` в приложении доки, её примерах и блоках.
- Движок: VitePress 2 (с 2026-10-17, `2.0.0-alpha.20`: v1 несовместим с Rolldown из Vite+) со своей темой с нуля (без DefaultTheme и его CSS, без `vp-raw` и
  `postcssIsolateStyles`); остаются markdown→Vue, SSG с гидратацией, i18n-маршруты,
  `@localSearchIndex`, проверка битых ссылок.
- Локали: RU в корне (эталонный текст), EN под `/en`, обе в одном изменении.
- Примеры — настоящие SFC, по файлу на локаль (`apps/docs/examples/{ru,en}/<comp>/<Name>.vue`):
  один файл рендерится в превью и показывается в коде; скрипт паритета сравнивает AST RU/EN с
  точностью до строк. Встроенные тексты берутся из словаря kit.
- Шаблон страницы компонента: заголовок и одна фраза → превью/код → установка → использование
  (конфигуратор на страницах с визуальными пропами) → анатомия (составные) → примеры →
  доступность (таблицы клавиш и ARIA) → API внизу (Props, Events, Slots, Exposed, CSS; раздел
  на каждую часть). Справа оглавление.
- API генерируется на сборке (`vue-component-meta`, TypeScript API по `.d.ts`, каталоги
  словаря, разбор CSS); RU/EN-описания живут в `apps/docs/api/<name>.ts`; проверка падает на
  отсутствующем или устаревшем описании. Каждый компонент типизирует слоты через `defineSlots`.
- Таблицы API на экране до 40rem идут в две колонки: имя с типом и значением по умолчанию под ним
  и описание. Четыре колонки (660 px) прокручивались вбок внутри 340 px без подсказки, и описание
  на телефоне не было видно (2026-11-14). Колонки переключаются после монтирования
  (`useMediaQuery` кита), серверная разметка остаётся настольной.
- Каркас: верхняя панель на всю ширину над липкими сайдбаром и оглавлением; на телефоне
  сайдбар в ящике. Playground остаётся e2e-фикстурой; у доки свой e2e и axe по всем страницам.
- Текст: правило `docs-writing.rule.md` и линтер прозы в `pnpm check`; четыре эталонные
  страницы (Кнопка, Выбор, Карточка, Начало) проходят ревью пользователя до массового выката.
- Подсветка кода: блок кода kit принимает токены строк от любого подсветчика и рендерит
  простой код без них; цвета — `--color-syntax-*`. С 2026-10-17 карта скоупов Shiki живёт в ките
  (ленивый вход `@numior/primitives/shiki`, встроенный подсветчик `useHighlighter`), дока
  берёт из него `shikiTokens` и сама решает только, какой язык у фрагмента.
  Подсветчик сборки один на процесс (`getSingletonHighlighter` в `config.ts`): VitePress
  исполняет конфиг заново при каждом перезапуске dev-сервера, а отдельные экземпляры делят
  один движок регулярных выражений и не освобождают его память. На 51-м экземпляре движок
  отказывал («fail to memory allocation»), сервер отдавал 500 на каждый модуль с кодом, а
  рамки блоков оставались белыми.
- Утилиты становятся модульными (`layout`, `spacing`, `sizing`, `typography`, `color`,
  `shape`, `prose`) с явными exports и манифестом `utilities.css`; проза (`.nui-prose`)
  стилизует только «голые» элементы контента и никогда не перебивает классы компонентов.
- Композаблы и хелперы получают свой раздел и справочники; сигнатуры — из `.d.ts`.
- LLM-доступ: `/llms.txt`, `/llms-full.txt` (EN) и RU-копии, markdown-двойник каждой
  страницы, локальный stdio-пакет `@numior/mcp` (только чтение, `check_usage` проверяет шаблон
  против API); всё читает один справочный бандл `docs:reference`.
- Порядок: сначала вся волна kit для доки, затем инфраструктура доки, эталоны и ревью,
  выкат, главная/«Темы»/справочники, блоки, в конце llms и MCP.

### Волна kit для доки (этап 1)

Токены: шкала заголовков `--text-xl…4xl`, начертания `--font-weight-*`,
`--leading-relaxed`, `--tracking-tight`, `--container-prose`; радиусы выводятся из
`--radius-base` (`sm` = ½, `md` = 1, `lg` = 1½, `xl` = 2); `--color-surface-code` и
`--color-syntax-*` (keyword, string, number, function, type, tag, attribute, property, comment,
punctuation, highlight) с контрастом ≥ 4.5 к поверхности кода в обеих схемах; пресеты акцента
в отдельном `@numior/tokens/accents.css` классами `nui-theme--accent-<имя>` (indigo, blue,
violet, emerald, teal, rose, orange, amber, slate) — пресет задаёт только пару
`--color-primary` и `--color-primary-foreground`; `-soft`, `-soft-foreground` и `--color-ring`
производные и считаются по месту, поэтому акцент работает и на вложенной области (с
2026-11-14, `tailwind-first.adr.md`, п. 3). Сборка CSS-пакетов (`scripts/build-css.ts`)
инлайнит относительные `@import`, как сборка `@numior/vue`.

Утилиты: `utilities.css` — манифест `@import`, модули `layout` (display, flex, grid,
`nui-grid-auto` с `--nui-grid-min`), `spacing` (только логические свойства), `sizing`,
`typography`, `color`, `shape`, `prose` — каждый самодостаточен и экспортируется отдельно.
`.nui-prose` стилизует элементы без класса вне `.nui-not-prose` через `:where()`, поэтому
его правила сильнее сбросов страницы (`h2 { … }`) и никогда не сильнее класса компонента;
модификаторы `--size-sm|lg`, ритм в `em`.

Примитивы: `useClipboard` (`supported` false-first, `copied` на `copiedDuration`),
`useHotkey('mod+k', handler, { enabled, target, inEditable })` — `mod` принимает Ctrl или Meta,
остальные модификаторы совпадают точно, редактируемые цели пропускаются, каркас переводит
на него Ctrl/Cmd+B; `useScrollSpy(ids, { root, rootMargin })` на IntersectionObserver —
активен первый видимый заголовок в полосе (по умолчанию верхние 40 % области), а когда
видимых нет, последний ушедший вверх; на сервере `undefined`. Цветовая схема:
`createNuiConfig({ colorScheme })` создаёт один общий контрол на приложение
(`useColorScheme()` без опций возвращает его, с опциями — локальный на область), `cycle()`
идёт light → dark → system, `colorSchemeScript(storageKey)` — строка инлайн-скрипта для
`<head>`, ставящая класс `nui-theme--<схема>` из хранилища до первой отрисовки. Контрол безопасен для
гидратации: до монтирования `scheme` равен серверному значению (`initial` или `system`),
хранилище, класс области и `prefers-color-scheme` читаются в `start()` — его вызывает
`useColorScheme()` в `onMounted` и любая запись (`set`, `toggle`, `cycle`); поэтому разметка,
зависящая от схемы (точка радио-пункта меню, иконка), совпадает с SSR, а тема до гидратации
держится на инлайн-скрипте.

Иконки: алиасы sun, moon, monitor, copy, hash, link, languages, command, arrow-left,
arrow-right, code, eye, terminal, chevrons-up-down, chevron-up, smartphone, tablet, maximize,
grip-horizontal — для переключателя темы, языка, копирования, якорей заголовков, поиска,
вкладок превью/кода и рамки блоков. Кнопка: `href`/`to`/`as` переводят `NuiButton` на ссылку
(`<a>` или компонент роутера) с тем же оформлением; `disabled` ссылки — `aria-disabled`,
`tabindex="-1"` и без `href`, `loading` отменяет переход; `destinationAttrs` общий с NuiLink.

NuiSeparator: `role="separator"` (или `none` при `decorative`), `orientation`, подпись между
линиями через `label` или слот; подпись получает `id` из `useId`, и разделитель берёт из неё имя
через `aria-labelledby` (дети `role="separator"` презентационны, текст внутри имени не даёт;
решение владельца 2026-11-14); у `decorative` связи нет; вертикальный растягивается на высоту
строки. NuiKbd: `keys` —
комбо `'mod+k'` или список, платформа определяется после монтирования (SSR и первый кадр —
`Ctrl`, на Apple после гидратации `⌘`), `platform` переопределяет; `variant="plain"` без
рамок для шорткатов меню — `NuiMenuRow` рендерит `shortcut` через него, поэтому строки
`'mod+r'` и готовые глифы работают одинаково.

NuiCode: `code` плюс необязательные `tokens` — строки из `{ text, scope }` от любого
подсветчика (scope из фиксированного списка keyword, string, number, function, type, tag,
attribute, property, comment, punctuation, variable), без токенов — простой текст; цвета
только из `--color-syntax-*`. Заголовок с `title` или `language`, кнопка копирования
(`useClipboard`, глифы copy → check растворяются друг в друга, `role="status"` объявляет
«Скопировано»), номера строк CSS-счётчиком (не копируются), подсветка строк `highlight`,
перенос `wrap`, `maxLines` сворачивает длинный код за кнопкой «Показать всё» с плавной
высотой через `useBlockSizeTween`. Прокручиваемая область фокусируемая. Тексты — каталог
`code`.

NuiToggleGroup: `items` с иконкой и подписью, одиночный (`role="radio"` + `aria-checked`,
`required` запрещает снять выбор) или `multiple` (`aria-pressed`, модель `values`), варианты
`outline` (сросшиеся кнопки) и `segmented` (подложка с приподнятым выбранным элементом),
`iconOnly` с `aria-label`, `orientation`; стрелки только переносят фокус
(`useListNavigation`, покой на выбранном), выбор — Space/Enter/клик. Модель и ключи — общий
`useOptionSelection`.

NuiCollapsible: кнопка с `aria-expanded`/`aria-controls`, необязательная обёртка-заголовок
`headingLevel`, панель на `grid-template-rows: 0fr → 1fr`; содержимое получает
`hidden="until-found"` только после завершения схлопывания (по `transitionend`), поэтому
поиск по странице находит закрытые разделы (`beforematch` открывает), а анимация закрытия
видит контент до конца; варианты `plain` и `card`. NuiAccordion: контекст открытых значений
(`modelValue` или `values` при `multiple`, `collapsible` запрещает закрыть последний),
`NuiAccordionItem` рендерит NuiCollapsible, стрелки и Home/End ходят по заголовкам.

NuiCommand: поле `role="combobox"` с виртуальным фокусом (`aria-activedescendant`) над
NuiList (`selectable="single"`, `keyboard=false`), группы, иконки, описания, шорткаты через
`NuiKbd` (поле `shortcut` у записей списка), фильтр по подписи, описанию и `keywords` либо
`filter=false` для серверного поиска с `search`, первый результат активируется до рендера,
Enter выбирает активный, `select` не хранит выбор. NuiCommandDialog оборачивает его в
NuiDialog с `placement="top"` и `bare` (заголовок скрыт визуально, тело без отступов, кнопки
закрытия нет — Esc в поле), горячая клавиша `mod+k` через `useHotkey`, выбор закрывает.

NuiToc: `nav` с подписью из словаря, вложенные `ol` ссылок `#id`, текущий раздел от
`useScrollSpy` помечен `aria-current="location"` и полосой у начала; собственная разметка, а не
NuiList, потому что оглавление — ссылки-якоря без выбора и roving-фокуса. NuiSkipLink:
фиксированная ссылка, видимая только в фокусе; по активации переносит фокус на цель
(`tabindex="-1"` при необходимости) и обновляет hash без прокрутки истории.

NuiSplitter: две панели со слотами `start`/`end`, разделитель `role="separator"` с
`aria-valuenow` в процентах и `aria-controls` первой панели; доля первой панели — модель
`ratio` в границах `min`/`max`, пишется в `--_ratio` и раскладывается через `flex-basis`;
перетаскивание с захватом указателя (учитывает RTL), стрелки шагают на `step`, Home/End —
к границам; ориентация `horizontal`/`vertical`. Нужен рамке блоков в доке.

Каркас: `header="full"` кладёт панель над строкой «сайдбар + контент + колонка `end`»
(`--_sticky-top` = высота панели), `sticky` прилипает сайдбар и колонку `end` к области
просмотра, когда прокручивается сама страница; колонка `end` (`endWidth`) скрыта на узких
экранах и при `sticky` берёт высоту по содержимому, не выше окна (2026-11-12): колонку во всю
высоту окна конец строки выталкивал вверх, как только под строкой появлялся футер, и короткое
оглавление уезжало под шапку; сайдбар остаётся во всю высоту и уходит вверх вместе со строкой; модификатор `--pending` до монтирования прячет десктопный сайдбар под 48rem, чтобы
телефон не мигал сайдбаром до гидратации; `useLayout` экспортирован. NuiSidebarGroup
`collapsible` сворачивает группу за подписью-кнопкой (`aria-expanded`, `inert`), NuiSidebarSub
раскрывается сам, когда вложенный пункт становится текущим (контекст `reveal`).

Далее в волне: `defineSlots` во всех компонентах;
кнопка-ссылка; NuiSeparator, NuiKbd, NuiCode, NuiToggleGroup, NuiCollapsible/NuiAccordion,
NuiCommand, NuiToc, NuiSkipLink, NuiSplitter; режимы NuiLayout.

### Каркас доки (этап 2, шаг 1)

Тема VitePress написана с нуля: `theme/index.ts` отдаёт `Layout` и регистрирует kit,
`config.ts` типизирован через `defineConfigWithTheme<DocsThemeConfig>` (`nav`, `sidebar`,
`texts` на локаль, `search.provider = 'local'`), `appearance: false` и инлайн
`colorSchemeScript('nui-theme')` в `head` вместо скрипта VitePress. `Layout.vue` —
NuiLayout со встроенным NuiSkipLink (с 2026-10-17 каркас ставит его сам, отдельной страницы нет) (`header="full"`, `sticky`, `end-width`, мобильный порог 64rem) с частями `parts/*`:
DocsHeader (NuiAppBar: триггер сайдбара на телефоне, словомарка, разделы, кнопка поиска с
NuiKbd, меню темы на NuiMenuRadioGroup поверх общего контрола, меню языка со ссылками на ту
же страницу другой локали), DocsSidebar (NuiSidebar и сворачиваемые группы из конфига),
DocsPage (`<article class="nui-prose">` с `Content` и пейджер на NuiCard), DocsToc (NuiToc по
`page.headers` 2–3 уровней), DocsHome, DocsNotFound (NuiEmpty), DocsSearch (NuiCommandDialog
без собственного фильтра над MiniSearch-индексом `@localSearchIndex` локали; пустой запрос
показывает страницы сайдбара). `useDocs()` даёт тексты локали, ссылки локалей, плоский список
страниц, пейджер и проверки текущего пути. Стили — только классы утилит: ни одного `<style>`.

Markdown-правила (`.vitepress/markdown`): fence → `<NuiCode>` с токенами Shiki
(`github-light` только как источник скоупов, цвета — `--color-syntax-*`; `title=`, `{2,4-6}`,
`:line-numbers`), JSON пропов экранируется в атрибуте целиком (`&`, `'`, `<`, `>`), иначе
индекс поиска и парсер шаблона видят обрывки; ссылки → `<NuiLink>` (внешние с `external`);
`::: tip|info|warning|danger` → NuiAlert, `::: details` → NuiCollapsible; якорь заголовка
рендерится собственным пермалинком `<a class="nui-prose__anchor">` с подписью на языке
страницы — простым `<a>`, а не компонентом, потому что индексатор поиска VitePress режет
страницу на разделы по `<hN>…<a href="#…">`. Часть `nui-prose__anchor` живёт в модуле prose
(символ `#` появляется при наведении и фокусе). Старые страницы с `vp-raw`/`demo.css`
собираются в новом каркасе до выката (этап 4).

### Примеры доки (этап 2, шаг 2)

Примеры — настоящие SFC в `apps/docs/examples/{ru,en}/<компонент>/<Имя>.vue`; папка с
`index.vue` и соседними файлами — многофайловый пример. Vite-плагин `docsExamples`
(`.vitepress/examples/plugin.ts`) отдаёт виртуальный реестр `virtual:nui-examples`
(локаль → имя → ленивый импорт) и по модулю `virtual:nui-example/<локаль>/<имя>` на пример:
компонент плюс исходник и токены Shiki каждого файла, с `addWatchFile` на файлы примера для
перезагрузки; сам реестр обновляется через watcher dev-сервера (`configureServer`: добавление и
удаление файлов под `examples/` инвалидирует модуль и шлёт полную перезагрузку), потому что
каталог, переданный в `addWatchFile`, Vite в dev считает импортом модуля и не может разрешить.
Виртуальные id вместо `?query` на `.vue`, потому что плагин Vue считает любой запрос к
`.vue` без `vue&type` главным модулем SFC и пытается его скомпилировать. В markdown
`<Example name="button/Basic" />` (`DocsExample` → `Suspense` → `ExampleView` с
`await loadExample` → `ExampleFrame`): переключатель «Превью | Код» на NuiToggleGroup,
опции «обратная тема» (класс `nui-theme--light` или `nui-theme--dark`, противоположный разрешённой схеме) и «справа налево»
(`dir="rtl"`) на рамке превью, копирование текущего файла через `useClipboard`, вкладки
файлов на NuiTabs, код в NuiCode (`maxLines` 30); всё на классах утилит, рамка превью —
`role="group"` с именем. Паритет RU/EN проверяет `pnpm docs:check`
(`apps/docs/scripts/check-examples.ts` → `parity.ts`): сигнатура шаблона по AST
`@vue/compiler-core` (теги, имена атрибутов, директивы с выражениями), скрипт и прочие файлы
без строковых литералов; отдельно — отсутствующая пара и блок `<style>`. Примеры входят в
Fallow как entry, `en/**` исключён из поиска дублей. Правило для новых компонентов и
скилл `nui-component` ссылаются на этот формат.

### Справочный бандл (этап 2, шаг 3)

`pnpm docs:reference` (`apps/docs/scripts/reference.ts` → `.vitepress/reference/build.ts`)
собирает `apps/docs/.reference/bundle.json` (в `.gitignore`, схема `version: 1` в
`reference.types.ts`): компоненты `@numior/vue` и `@numior/forms` по экспортам `index.ts`
через `vue-component-meta` (пропы с типом без хвоста `| undefined`, `kind`

справочника передаёт свой анализатор в `buildReference`, второго не создаётся.

`vp run --cache` — генерация и примеры читают `dist`, и устаревшая сборка роняла запуск

Справочник нескольких компонентов на одной странице показывает общий каталог текстов и общую

### Конфигуратор и поиск по API (этап 2, шаг 4)

`<Configurator name="NuiButton" />` (`DocsConfigurator` → `Suspense` → `ConfiguratorView` →
`ConfiguratorFrame`) берёт из справочного бандла перечень пропов и содержимое, заданные в
`apps/docs/api/<семейство>.ts` (`configurator: { props, content }`; `docs:check` падает на
несуществующем пропе). Панель — NuiField на каждый проп: enum → NuiSelect по литералам,
boolean → NuiSwitch, number → NuiNumberField, string → NuiInput, плюс поле содержимого;
состояние держится в типизированных картах по роду пропа (`configuratorState`), живой

текст API через `themeConfig.search.options._render`: к исходнику страницы дописываются
разделы `### <компонент>` с пропами, моделями, событиями и слотами и описаниями на языке
страницы (`apiSearchText`), так что описания пропов находятся по Ctrl+K.

### Правки kit после ревью эталонов (2026-09-27)

Ревью пользователя показало пробелы kit, которые дока сделала видимыми. `@numior/tokens/base.css`

### Сцены конфигуратора (2026-11-12)

Составному компоненту голый тег без данных нечего показать, поэтому конфигуратор принимает
сцену: `configurator: { scene: '<семейство>/Example', props, values, choices }`. Сцена — обычный
пример из `examples/{ru,en}` со своими данными из `#demo`. Выбранные свойства приходят в сцену
как атрибуты: компонент стоит единственным корнем или получает `v-bind="$attrs"` (с одним
корнем-обёрткой нужен `inheritAttrs: false`). Вкладка «Код» печатает исходник сцены
(`sceneCode`): служебные `$attrs` и `defineOptions` убираются, выбранные свойства встают первыми
в тег компонента, тег переносится по строкам за шириной 100, как это делает форматтер. Файлы
данных идут вкладками через общую часть `ExampleFiles` (она же в рамке примера).

`choices` сужает список значений enum, когда часть значений вне сцены не имеет смысла
(`floating` у дерева). Сборка справочника (`reference/scenes.ts`) падает, если сцены нет в одной
из локалей, в ней нет компонента, свойства до него не доходят, сцена сама задаёт настраиваемое
свойство или рядом со сценой указано `content`. Выключенный флаг без значения по умолчанию
в код не печатается (раньше выходило `:disabled="false"`).

### Дока для языковых моделей (2026-11-12)

Каждая страница навигации получает копию в Markdown по адресу страницы с окончанием `.md`
(`/components/button.md`, `/en/components/button.md`). Копию строит `.vitepress/llms/twin.ts` из
исходника страницы: фронтматтер и контейнеры убираются, `<Example>` и сцена `<Configurator>`
печатаются кодом файлов примера (файлы данных магазина подписаны именем), `<ApiReference>`
становится импортом и таблицами свойств, моделей, событий, слотов, методов и текстов,
`<KeyboardReference>`, `<TokenReference>` и `<IconReference>` — таблицами, `<SignatureReference>`
— блоками `ts`. Источник тот же, что у страницы: справочный бандл и файлы примеров, поэтому
копия не расходится с сайтом.

- Каталоги по соглашению llmstxt.org: `/llms.txt` и `/llms-full.txt` на английском,
  `/llms-ru.txt` и `/llms-full-ru.txt` на русском; каталоги ссылаются друг на друга в разделе
  `Optional`. Список страниц берётся из `NAVIGATION` (`navigationPages`).

  `Accept: text/markdown`, потому что по адресу `.md` VitePress отдаёт модуль страницы.
- В `<head>` страницы стоит `<link rel="alternate" type="text/markdown">`.
- Кнопки «Скопировать страницу» нет: решение владельца 2026-11-16 — страница для ассистента
  доступна через `/llms.txt`, копию `.md` и сервер MCP, отдельная кнопка на странице не нужна.
  `useClipboard().copy` по-прежнему принимает промис с текстом (одна запись `ClipboardItem` с
  отложенным содержимым, иначе Safari отклоняет запись после `await`).

### Стили в блоке «Установка» из кода (2026-11-15)

Заменено 2026-11-18 (раздел «Установка одной строкой» ниже): стили подключает плагин кита, блок
«Установка» — импорт без списка CSS.

На 35 из 53 страниц компонентов блок «Установка» перечислял не все CSS: у Select три файла
из двенадцати, у «Книги» не было стилей графиков. Решение владельца: список строится из кода.

- Справочник считает для каждого компонента `stylesheets` (`reference/stylesheets.ts`): граф
  модулей от SFC компонента по импортам SFC и TS, через реэкспорты и подпути `@numior/*`
  (условие `@numior/source`); SFC даёт файл своей папки из `styles.css` пакета. Если в папке
  файлов несколько или своего нет, берутся файлы пакета, где описаны блоки её шаблона.
  Корневой класс другого компонента того же пакета в шаблоне (`nui-list` у `NuiTree`) добавляет
  файл того компонента; между пакетами так можно только с `nui-content` редактора
  (`pnpm check:styles`). Файл без отдельного экспорта `./styles/*.css` заменяется `styles.css`
  пакета, и тогда отдельные файлы этого пакета не печатаются.
- Порядок — порядок `@import` в `styles.css` пакетов; пакеты от базовых к зависимым, как
  каскад общего файла.
- Блок ```` ```ts install ```` получает строки CSS при сборке страницы, в копии для ИИ и в
  данных `@numior/mcp`; ```` ```ts install:packages ```` печатает `styles.css` пакетов (разделы
  «Таблица» и «Книга»). Без справочника сборка падает, а не печатает пустой список.
- Проверка `install-styles` отклоняет CSS кита, перечисленный вручную в блоке установки или
  рядом с импортом компонента, и блок «Установки» с компонентом без `install`.
- Команды установки модулей нет (с 2026-11-17, решение владельца «один пакет `@numior/kit`»):
  все модули приходят с `pnpm add @numior/kit` из «Начала работы». Прежде (2026-11-15) сборка
  печатала перед блоком `install` вкладки менеджеров с пакетами модуля.
- Ручной импорт `styles.css` модуля проверка не пропускает: такой блок пишется
  ```` ```ts install:packages ````. Модуль — подпуть кита со своим `<модуль>/styles.css` в
  `exports` (`@numior/kit/table/`), список строится из `packages/kit/package.json`.
- Отвергнуто: ручной список с проверкой полноты — список всё равно пишется руками и правится
  при каждой новой части; разбор классов шаблона как единственный источник — контекстные
  селекторы чужих файлов дают ложных владельцев блока.

### Дока называет только `@numior/kit` (2026-11-17)

Решение владельца: приложение ставит один пакет `@numior/kit`, модули берутся из подпутей
(`modular-foundation.adr.md`). Дока, копии для ИИ и данные MCP говорят на языке приложения.

- Справочник считает по внутренним пакетам (исходники, типы, `styles.css` пакетов), а на выходе
  переводит имена в подпути кита (`reference/kit-entries.ts`): `package` компонента и
  объявления, `styles.import`, `stylesheets`, список стилей бандла. Карта читается из
  `exports` кита и его исходников-реэкспортов (`export * from '@numior/vue'`,
  `@import '@numior/table/styles.css'`); папка `styles/` пакета переходит в `styles/` подпути,
  если кит отдаёт `./<подпуть>/styles/*.css`. Имя без входа в ките роняет сборку справочника
  с подсказкой добавить вход в `packages/kit`.
- Проверка `imports` отклоняет внутренние имена `@numior/*` на страницах, в примерах, в данных
  `#demo` и в каталогах (`api/*.ts`, навигация, тексты, главная); разрешены `@numior/kit…` и
  `@numior/mcp`. Прежняя проверка «имя есть в названном пакете» (композабл из `@numior/vue`

Раздел `/blocks/` показывает готовые экраны кабинета магазина. Блок — пример

### Правки kit после второго ревью (2026-09-27, вечер)

- `useHotkey` сравнивает комбинацию и с `event.key`, и с физической клавишей из `event.code`
  (`KeyK` → `k`, `Digit1` → `1`): в русской раскладке Ctrl+K приходит как «л» и раньше не
  совпадал. Комбинации с Ctrl/Meta срабатывают и в полях ввода (как поиск в VitePress и
  shadcn); одиночные клавиши по-прежнему пропускают редактируемые цели; `inEditable: false`
  возвращает защиту явно (`NuiLayout` для `mod+b`, чтобы не спорить с жирным текстом в
  редакторах). Слушатель — `onKeyStroke` из VueUse.
- `useScrollSpy` возвращает `{ activeId, activate, measure }` и считает текущий заголовок по
  прокрутке, как VitePress: последний заголовок, чей верх выше линии на 20% высоты прокрутки
  (`line`, доля 0–1, у `NuiToc` — проп `line`). IntersectionObserver не подходит: заголовок,
  перепрыгнувший полосу целиком, не даёт события и оставался «пройденным», поэтому клик по
  третьему с конца пункту подсвечивал последний. Правило «внизу страницы активен последний»
  удалено. `activate(id)` из клика по оглавлению фиксирует выбранный пункт до `scrollend`
  (запасной таймер 150 мс после последнего `scroll`). `NuiToc` вызывает `activate` в `select`.
- `NuiSelect`: `.nui-field` получил `grid-template-columns: minmax(0, 1fr)`, корень и триггер
  — `min-inline-size: 0`, ширина шеврона считается от размера шрифта
  (`calc(1.25 * var(--_font-size))`), поэтому длинная подпись обрезается многоточием, а крестик
  не наезжает на текст; `.nui-combobox__input` тоже обрезается многоточием.
- `NuiTree` ставит курсор на узел уже в `pointerdown`, поэтому `focus` корня не подсвечивает
  выбранный или первый узел на время до `click`; фон активного узла показывается только при
  клавиатурном фокусе на дереве (контекст дерева отдаёт `activeId`, пока корень в фокусе и
  последнее действие пришло с клавиатуры, класс `nui-list-item--active`; после клика мышью
  строка держит только `selected`, как опция списка без `:focus-visible`; до 2026-09-30 —
  `.nui-tree:focus .nui-tree__item--active`).
- `to` типизирован как `NuiRouteLocation` (`string | object`), приложение сужает его через
  `declare module '@numior/vue' { interface NuiRouteRegister { location: RouteLocationRaw } }`.
- Контрол вне `NuiField` всегда рисует свою обёртку `.nui-field` (для чекбокса, переключателя
  и радио — `.nui-field--inline` с `inline-grid`), тексты появляются только при наличии:
  раньше обёртка возникала вместе с первой ошибкой, корень менялся и Vue пересоздавал
  `<input>`, теряя фокус при вводе. `NuiFieldFrame` остаётся функцией рендера: `<slot>` в
  шаблоне компилируется во фрагмент, а SFC не может вернуть элемент слота своим корнем.
- `NuiSidebar variant="plain"`: списки групп сдвинуты под подпись с направляющей линией, как
  подсписки `NuiSidebarSub`.
- `NuiCode`: пустые строки держат высоту `1lh`; токен `--color-syntax-variable`; инлайн-код в
  прозе окрашен токеном `--color-code-inline`; оба добавлены в пресет Tailwind.

  последними, после того как текущие правки этих пакетов лягут в `master`.
- Страницы «Версии» нет (решение владельца 2026-11-12): таблица SemVer пересказывала
  общеизвестное. Единственный неочевидный факт — общий номер версии всех пакетов `@numior/*` —
  стоит одной фразой в разделе установки «Начала работы». Срок поддержки прошлой старшей
  версии появится вместе с первой такой версией.

### Установка одной строкой (2026-11-18)

Решения владельца после плагина `numior()` (@.archcore/modular-foundation.adr.md): компоненты и их CSS
подключаются по использованию, поэтому дока не перечисляет стили.

- Блок «Установка» на странице компонента — обычный ```` ```ts ```` с импортом; пометки `install` и
  `install:packages`, сборка списков CSS при рендере, в копии для ИИ и в данных MCP убраны.
- Блок «Стили» в API компонента убран, и в копиях для ИИ тоже; `stylesheets` компонентов и бандла,
  `styles.import` из справочника ушли. Файлы `styles/*.css` в ките остаются.
- Проверка `component-styles` не пропускает блок кода, который подключает CSS отдельных компонентов
  или модуля (`@numior/kit/styles/*.css`, `@numior/kit/<модуль>/styles.css`): их приносит
  `@numior/kit/styles.css`. Тема, пресет Tailwind, `prose.css` проходят. Та же проверка не пропускает
  CSS кита, подключённый из скрипта (`import '@numior/kit/….css'`) или из блока `<style>` в примере
  `vue`: стили собирает Tailwind приложения, и подключаются они только во входе Tailwind (как правило
  `misplaced-styles` в MCP).
- «Начало работы» и «Tailwind» переписаны под K4: установка одной командой, плагин `numior()` в
  `vite.config.ts`, три строки во входе Tailwind, тема меняется блоком `@theme`; «Tailwind» объясняет,
  что стили компонентов написаны через `@apply` и собираются Tailwind приложения, и что классы на
  компоненте сильнее его стилей (слой `utilities` после `components`).
- Шаги «Начала работы» пишутся в Markdown блоком `:::: steps` (четыре двоеточия, чтобы внутри жили
  `::: code-group`): блок обязан начинаться с `### `, каждый `###` открывает шаг. Правило разметки
  выводит `NuiStepper readonly` с `NuiStepperStep` на шаг, заголовок `<h3>` уходит в слот `#title`
  (оглавление и якорь остаются) и получает класс `scroll-mt-20`: заголовок в шаге — не проза, а
  отступ прокрутки под шапку сайта — забота доки. Своя часть доки для шагов не нужна.
- Фразы «подключите `kbd.css`» (Tooltip), «`skeleton.css`» (Card) и «`table/styles.css`» (вид таблицы в
  контенте) удалены: эти стили приходят по манифесту.

## Alternatives Considered

- Бренд как тема kit по умолчанию: чужим продуктам пришлось бы перекрашивать kit, а токены
  получили бы ломающее изменение.
- Точный Ember заливкой с тёмным текстом в обеих схемах: требует развести в kit primary-заливку
  и primary-текст примерно в 38 файлах стилей.
- Каменный знак или 3D-сцена на первом экране: лицо библиотеки составляют её компоненты, а
  WebGL на главной спорит с обещанием скорости.
- Оставить DefaultTheme и переопределять его стили: дока не доказывает самодостаточность
  kit, а конфликт стилей (`vp-raw`) остаётся.
- Своё приложение на Vite + SSG или Nuxt Content: больше собственной инфраструктуры
  (роутинг, поиск, SSG), пока Nuxt-модуля нет.
- Пресеты акцентов в hex внутри `theme.css`: нет тёмных вариантов и растёт обязательный файл.
- Один набор примеров на английском: RU-страницы показывали бы английские демо.

## Consequences

Волна kit добавляет части, нужные любому приложению, а не только доке. Правило
`engineering-quality.rule.md` («изменение поведения отражать в RU/EN docs») на время волны
выполняется через список задолженности выше. `component-authoring.rule.md` требует от нового
компонента доку (примеры RU/EN, описания API, страница), как только новая инфраструктура
доки существует.
