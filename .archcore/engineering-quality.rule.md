## Rule

Писать код kit с нуля. Соблюдать направления зависимостей и публичные exports. Не добавлять heavy engines в базовый UI, DOM/Vue в независимые ядра или обязательный Tailwind. Не менять публичный контракт без документации и проверки совместимости.

Сохранять SSR, keyboard/focus, RTL, light/dark/system, semantic colors и density. Все темы используют общие CSS tokens. Не заявлять WCAG, Excel compatibility и performance без проверяемых данных. Не маскировать отсутствующие тесты passWithNoTests и не отключать проверки целиком ради CI.

Проверять lint, формат, типы, Fallow, unit, сборку, документацию и браузерные сценарии перед передачей изменений. Исключения Fallow должны иметь узкий scope и объяснение. Любое изменение пользовательского поведения отражать в RU/EN docs. Не публиковать пакеты до принятого полного 1.0.

## Rationale

Быстрая разработка должна сохранять корректность и ремонтопригодность. Отдельные проверки защищают шаблоны, граф зависимостей и реальные сценарии, которые один линтер не покрывает.

## Examples

Good: приложение импортирует @numior/vue и явно CSS; пользователь меняет --nui-primary; новый сценарий клавиатуры проверяется в браузере.

Bad: кнопка импортирует spreadsheet через общий barrel; все packages/** исключены из Fallow; screenshot подменяет проверку сохранения документа; deferred HTML сохраняется без flush.

## Enforcement

Корневые scripts и CI; архитектурные зоны Fallow; TypeScript strict; Oxlint и отдельные Vue template rules; Vitest/Playwright. Инструкции для агентов в AGENTS.md указывают на принятый план и реальные команды. Archcore status проверяет структуру документов. Изменения требований обновляют существующие документы и связи.
