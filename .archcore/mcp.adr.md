## Context

Продуктовый сайт (`docs-site.adr.md`) обещает доступ для LLM: копии страниц в Markdown,
`llms.txt` и локальный stdio-пакет `@numior/mcp` только для чтения с проверкой `check_usage`.
Ассистент, который пишет код на Numior UI, ошибается одинаково: выдумывает компоненты и
свойства, ставит значение не из перечисления (`variant="primary"` у `NuiButton`), забывает CSS
компонента, стилизует части кита снаружи. Задача S17 плана доки; решения владельца от
2026-11-14 окончательные.

## Decision

Решения владельца (2026-11-14):

1. Данные вшиты в пакет. Сборка пишет один `dist/data.json`; сеть серверу не нужна, данные
   собраны из того же коммита, что и пакеты.
2. `check_usage` принимает код SFC и необязательное имя файла и возвращает диагностики с
   номером строки и подсказкой: неизвестный компонент `Nui*`, свойство или событие, значение
   вне перечисления, импорт имени, которого нет в названном пакете `@numior/*`, неподключённые
   стили компонента, стилизация блока, части или модификатора `.nui-*` снаружи. Неизвестному
   имени подсказывается ближайшее.
3. Пакет `private: true` до 1.0, бинарь `numior-mcp`, SDK `@modelcontextprotocol/sdk` 1.32.2
   точной версией.

Состав данных (`McpData`, `version: 1`, типы в `packages/mcp/src/data.types.ts`):

- `components` — справочник из `apps/docs/.reference/bundle.json` (`ReferenceBundle`) без путей
  к исходникам (`file`), `importTokens` и `configurator`; к каждому компоненту добавлены
  `stylesheets` и адреса страниц, где есть его раздел API;
- `catalogs` — встроенные тексты по пространствам имён, `exports` — имена компонентов и
  объявлений каждой точки входа справочника, `packageStyles` — пакеты с экспортом
  `./styles.css`;
- `tokens` и `icons` — из справочника;
- `pages.en`/`pages.ru` — Markdown-копии страниц из `llmsEntries`
  (`apps/docs/.vitepress/llms/files.ts`), второго генератора нет;
- `examples.en`/`examples.ru` — файлы примеров из `exampleSources` через `copyableSource`.

Версии в данных нет: сервер берёт её из `package.json` пакета при запуске, потому что
`semantic-release` переписывает версии манифестов в `prepare`, уже после сборки.

Инструменты (описания по-английски, у инструментов с текстом `locale`: `en` по умолчанию,
`ru`):

| Инструмент        | Ответ                                                                                    |
| ----------------- | ---------------------------------------------------------------------------------------- |
| `list_components` | JSON: имя, пакет, страница, лид страницы; фильтр `package`                               |
| `get_component`   | JSON справочника (импорт, CSS, свойства, модели, события, слоты, клавиши, тексты, токены) и копия страницы |
| `get_example`     | файлы примера Markdown-блоками; иначе имена той же семьи или ближайшее                   |
| `get_page`        | копия страницы; адрес принимается с `/en`, `.md`, `index`, origin и query                |
| `search`          | MiniSearch по заголовку, заголовкам разделов, лиду и тексту: путь, ранг, строка прозы    |
| `list_tokens`     | токены с light/dark; фильтр по группе                                                    |
| `list_icons`      | псевдонимы иконок; фильтр по подстроке псевдонима или имени Lucide                       |
| `check_usage`     | JSON `{ file, diagnostics: [{ line, column, severity, code, message, hint }] }`          |

`check_usage`:

- Шаблон разбирает `@vue/compiler-sfc` (`parse`, AST шаблона, `babelParse` для `<script>`),
  стили — `postcss` и `postcss-selector-parser`. Имя тега сверяется с импортами: локальный
  компонент с префиксом `Nui` не проверяется, псевдоним импорта из `@numior/*` ведёт к
  компоненту кита.
- Ошибки: `unknown-component`, `invalid-value`, `unknown-export` (включая импорт по
  умолчанию), `parse-error` разметки и скрипта. Предупреждения: `unknown-prop` и
  `unknown-event` (атрибуты и нативные события проходят насквозь, список не полный),
  `missing-styles`, `style-override`, `parse-error` стиля.
- Ближайшее имя — расстояние Левенштейна на уровне модуля и `minBy`, порог
  `max(2, длина / 3)`. Для `variant="primary"` подсказка называет свойство, которое принимает
  значение (`tone`); для числа в статическом атрибуте — привязку `:prop`. Перечисление длиннее
  12 значений не печатается, подсказка отсылает к `get_component`.
- CSS компонента — `ComponentReference.stylesheets` из справочника: файлы компонента и всех его
  частей в порядке `styles.css` пакетов (тот же список печатает блок «Установка» его страницы).
  Файл покрыт импортом самого листа или общего `@numior/<пакет>/styles.css`, в `<script>` или
  через `@import` в `<style>`; подсказка говорит, что стили могла подключить точка входа.
- Субъект селектора — составной селектор после последнего комбинатора; `:deep`, `::v-deep`,
  `:slotted`, `:is`, `:where` пропускают внутрь, в `<style module>` считается только
  `:global`, вложенность разворачивается, `@keyframes` пропускается. Блок ищется как в
  `scripts/check-kit-styles.mjs`; в отличие от него голый блок тоже предупреждение (решение
  2), а подсказка про размещение отправляет класс на свою обёртку. Владелец блока —
  компонент с тем же kebab-именем, свойства в подсказке — те, чьи значения дают модификаторы
  блока, токены — те, что совпадают со словами свойств правила.

Порядок задач (`packages/mcp/vite.config.ts`): `build` — `vp build`, затем
`node scripts/build-data.ts`, затем `vue-tsc`; он зависит от `reference`
(`pnpm --filter @numior/docs reference`), а тот — от сборки пакетов на концах графа
workspace, от которых никто не зависит (сейчас `nuxt`, `offline`, `tailwind`; список
вычисляется из манифестов). В `vp run --filter './packages/*' build` топологический порядок
ставит их после всех остальных пакетов, поэтому справочник читает свежие `dist`. Одиночный
`vp run @numior/mcp#build` пересобирает только концы графа и читает уже собранные `dist`
остальных. Скрипт данных — обычный Node с вырезанием типов: он импортирует модули доки по
путям с расширением `.ts`.

## Alternatives Considered

- Читать доку с сайта по сети — отвергнуто владельцем: нужна сеть, версия расходится с
  установленными пакетами.
- Собирать данные при первом запуске — в опубликованном пакете нет исходников доки.
- Второй генератор Markdown — дублировал бы `llmsEntries` и разошёлся бы с копиями сайта.
- `dependsOn` на сборку каждого пакета — Vite Task запускает такие задачи без
  топологического порядка: в одиночном запуске `vue-tsc` пакета `collaboration` стартовал,
  пока `dist` пакета `editor-vue` пересобирался, и сборка упала.
- Только `ReferenceStyles.import` как CSS компонента — `NuiSelect` без `field.css` и
  `list.css` выглядел бы подключённым.

## Consequences

`dist` весит около 5 МБ, из них `data.json` 4,8 МБ (103 компонента, 108 страниц и 276
примеров на локаль). Тесты: фикстурный бандл, харнессы `McpSession` (`InMemoryTransport`) и
`CheckedFile`, один тест на `dist/data.json` после сборки; `scripts/check-artifacts.mjs`
проверяет экспорты, shebang бинаря, состав данных и внешние зависимости. Импорты
проверяются только для точек входа справочника. `v-bind="объект"`, динамические аргументы и
выражения в значениях свойств не проверяются. Корневой `pnpm check` по-прежнему вызывает
`docs:reference` отдельным шагом, поэтому справочник строится дважды. Гайд `/guide/ai`
описывает установку, Claude Code, Cursor и инструменты.
