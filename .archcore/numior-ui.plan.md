## Goal

Создать независимый универсальный UI kit Numior UI для Vue 3.5+ и TypeScript: скорость, удобство, расширяемость, модульность и функциональность без платных клиентских модулей. Визуальные ориентиры — shadcn и современный VS Code; первый потребитель — SaleHub, далее CMS/CRM/ERP и сторонние приложения. Сам kit не содержит бизнес-логику этих продуктов. Миллионы пользователей — долгосрочная цель, не подтверждённая метрика.

План согласован в интервью. `accepted` означает принятие плана, а не завершение реализации. Разработка закрытая до полного первого стабильного релиза; публичных alpha/beta нет. Один разработчик и AI, фиксированного срока нет. Ускорение не должно снижать корректность, доступность и UX.

### Продукт и поставка

- Весь новый код писать самостоятельно; не копировать Ln из SaleHub. Поведенческие композаблы и утилиты — `@vueuse/core` и `lodash-es` там, где есть эквивалент с тем же поведением (`dependencies.adr.md`); ядро редактора своё, без Reka/ProseMirror/Tiptap в качестве основы. Узкие сторонние зависимости допустимы после проверки лицензии, размера, назначения и заменяемости.
- Весь клиентский код MIT: коммерческое использование, форки, расширения, редактор, таблицы, формулы, совместная работа и offline без платных client-only ограничений. Backend предоставляется через документированные адаптеры; обязательный бесплатный backend не входит в контракт.
- Официальные способы установки — npm и CLI. CLI копирует визуальные компоненты и стили; поведенческие ядра, editor/grid engines остаются npm-зависимостями. Команды `init`, `add`, `diff`, `update`; обновления сохраняют изменения пользователя и явно показывают конфликты.
- Два API: готовые стилизованные компоненты с props/slots и композиция из частей. Префикс компонентов `Nui`, CSS и утилит `nui-`; рабочее имя Numior UI. Внутренний npm scope `@numior` до проверки доступности перед публикацией.
- Vue — peer dependency. Независимые entry points и CSS: импорт кнопки не подтягивает редактор, spreadsheet, collaboration или Tailwind. ESM, tree shaking, SSR и Nuxt, безопасная гидратация.
- SemVer; breaking changes только в major, migration guides; предыдущий major получает security/critical fixes шесть месяцев после выхода нового.

### Архитектура и контракты

| Слой | Назначение |
| --- | --- |
| tokens/themes | Семантические CSS variables, темы, плотность и состояния |
| primitives/vue | Собственное доступное поведение, готовые Vue-компоненты и составные части |
| forms | Ручные Vue-формы и schema/config формы с общим состоянием |
| grid/spreadsheet | Простая таблица, DataGrid, собственные модели и вычислительное ядро |
| editor-core/editor-vue/content | Независимое ядро редактора, Vue UI и отдельный viewer/SSR |
| collaboration/offline | Адаптеры синхронизации и хранения, очередь операций, история |
| tailwind/nuxt/cli | Опциональные интеграции и инструменты распространения |

Направление зависимостей: фундамент → поведение/ядра → компоненты/адаптеры → приложения. Ядра не зависят от Vue и UI; базовый UI не импортирует тяжёлые модули. Yjs возможен как изолированный MIT-адаптер синхронизации, а не обязательный runtime всего kit.

Единый визуальный язык, темы light/dark/system, плотности comfortable/compact. Семантические роли primary, secondary, success, warning, error, info; surface, text, border, focus и контрастные foreground для состояний. Preset + runtime customization + scoped/nested themes; overlays сохраняют тему инициатора. Одинаковые токены питают CSS компонентов, собственные опциональные утилиты и интеграцию Tailwind 4. Работа без Tailwind обязательна.

Полные RU/EN документация и переводы компонентов; другие локали подключаются. Локализованные числа и даты, RTL с первого стабильного релиза. Поддержка двух последних стабильных Chrome/Edge/Firefox/Safari, включая Android Chrome и iOS Safari; точная проверенная матрица публикуется для релиза.

### Функциональный состав первого стабильного релиза

Базовые элементы и формы: кнопки, ссылки, текстовые и числовые поля, поле одноразового кода, textarea, checkbox/radio/switch, select/combobox/autocomplete, даты и диапазоны, upload, валидация и состояния загрузки/ошибок. Навигация и структура: layout, sidebar, меню, tabs, breadcrumbs, pagination. Обратная связь и слои: dialog/drawer/popover/tooltip, toast/notification, alert, progress/skeleton. Представление данных: card, badge, avatar, список, дерево, таблица. Сложные модули ниже обязательны в 1.0; перечень конкретных компонентов уточняется в спецификациях без исключения согласованных возможностей.

Формы: ручная композиция и schema/config API, синхронная/асинхронная валидация, серверные ошибки, условные поля, повторяемые группы и подключаемые контролы. Единые контракты значения, touched/dirty, reset, pending и submit.

Редактор: собственное ядро; rich text, изображения, таблицы, paste из Office, блоки в духе Notion, drag, slash menu, пользовательские блоки, совместная работа, комментарии и история. Внешний основной формат — HTML; внутреннее дерево может быть версионированным. Комментарии/история/синхронизация хранятся отдельно через адаптер со стабильными ссылками на узлы. Presets, настройка разработчиком и разрешённые автору параметры оформления. Одинаковая стилизация при редактировании и публикации; viewer/SSR не загружает editor runtime.

Большие документы: мгновенное видимое редактирование, отложенная сериализация HTML допустима. Перед валидацией/сохранением форма обязана дождаться flush свежего HTML. Reset, смена документа и внешнее обновление отменяют устаревший результат сериализации; сохранение старого снимка недопустимо.

DataGrid: сортировка, фильтрация, группировка, дерево, закрепление, виртуализация, редактирование, диапазоны, copy/paste. Два режима: полностью локальный/offline и серверная пагинация; производительность измеряется отдельно.

Spreadsheet: собственные модель и calc core; формулы, ссылки, перерасчёт, несколько листов, XLSX import/export, сложные отчёты с charts, pivots, conditional formatting и расширенными формулами. Матрица совместимости и проверяемый корпус Excel-файлов вместо обещания 100% Excel. Узкие кодеки допустимы; лицензии и round-trip проверяются. HyperFormula не принимается как MIT-основа; ExcelJS/SheetJS не считаются готовым полноценным вычислительным ядром.

Неподдерживаемая книга открывается read-only с отчётом об ограничениях и сохранением оригинала. Нельзя выдавать cached values за актуальный пересчёт или тихо повреждать файл при экспорте.

Offline для редактора и spreadsheet: локальное сохранение, очередь, восстановление после перезапуска и reconnect, версии схем/плагинов. Конфликт одной ячейки разрешается детерминированно с сохранением альтернативы в истории и восстановлением; решение не зависит только от ненадёжных локальных часов. Полное редактирование на мобильных обязательно; ёмкость и UX измеряются отдельно, без тихого усечения данных.

## Acceptance Criteria

- Чистая установка npm и CLI, одинаковое поведение source/npm; сохранение кастомизации при update, явные конфликты. Vite и Nuxt SSR/hydration без ошибок, viewer без editor runtime.
- Light/dark/system, runtime primary/secondary и остальные роли, состояния, compact/comfortable, RTL, nested scopes и overlays. Keyboard, focus restoration, screen reader, touch, IME и reduced motion. Цель WCAG 2.2 AA для компонентов и демонстраций, а не заявление о соответствии любых приложений.
- Формы: async/server validation, быстрый submit после ввода, reset и смена документа во время сериализации. Ни одного устаревшего HTML при сохранении.
- Offline/reconnect, повторные операции, crash/reload, конкурентные изменения одной ячейки, доступность альтернативы в истории, версии документов/плагинов.
- Формулы и XLSX проверять golden corpus, сравнением расчётов и round-trip; неподдерживаемые файлы read-only, оригинал доступен, ограничения видны. Проверять correctness до FPS.
- Размер и граф импорта подтверждают модульность. Base button не тянет тяжёлые движки и optional integrations.

Волна 7 (2026-09-28) сняла слово «прототип»: первый коммит каждого тяжёлого модуля — рабочее
ядро с бенчмарк-харнессом в репозитории, а цифры ниже — пороги приёмки, записанные в ADR модуля
(`grid.adr.md` первым). Это целевые нагрузки, не доказанные возможности. Серверный total в миллион строк не подтверждает локальную обработку миллиона. Фиксировать устройство, браузер, dataset, операции, память, длительность, холодный/тёплый старт и p95. Начальный ориентир обычного ввода p95 ≤100 ms на зафиксированном устройстве; долгие операции дают progress/cancel и не блокируют UI. Мобильные пределы измерять отдельно. Сравнения с другими библиотеками требуют одинаковых данных, функций и гарантий сохранности. Нельзя ухудшать поиск, выделение, copy, undo или доступность ради benchmark.

## Dependencies

- Наличие собственной реализации и постоянных тестов важнее количества внешних библиотек. Новые зависимости проверять на MIT-совместимость и отдельность подключения.
- Серверные storage/auth/collaboration/comments/history через документированные адаптеры; backend SaleHub не включён в данный репозиторий.
- Доступность npm scope, публичное имя и выпуск требуют проверки перед публикацией; текущий bootstrap приватный.
- Публикация и миграция production не входят в задачу начальной настройки.
