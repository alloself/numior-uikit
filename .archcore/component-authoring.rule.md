## Rule

Компоненты `@numior/vue` и примитивы `@numior/primitives`:

- Компонент — всегда SFC, во всех пакетах, в тестах, в песочнице и в примерах доков: никаких
  `defineComponent` с render-функцией, функциональных компонентов на `h` в `.ts`, объектов
  `{ setup, render }` и компонентов, объявленных внутри другого SFC. Вспомогательный компонент
  примера — соседний файл в папке примера (`examples/<locale>/<name>/<Example>/index.vue` и его
  части). Хост теста — фикстура `packages/<pkg>/test/fixtures/<Name>.vue`: драйвер или харнесс
  монтирует её с пропсами, содержимое слотов написано в её шаблоне, результат композабла выходит
  через `defineExpose`; SSR рендерит ту же фикстуру через `renderToString` из `@vue/test-utils`.
  Разметка живёт в шаблоне, логика — в функциях скрипта; горячий путь (ячейки таблицы) решается так
  же: ветки в шаблоне, данные из функций. Пустые ветки, которые оставили бы `<!--v-if-->`, рисуются
  `v-for` по списку частей. Слоты потребителя, которые нужны глубоко
  вложенной части рекурсивной структуры, не пробрасываются через каждый уровень шаблоном и не
  кладутся в inject. Динамические слоты (`<template v-for="name in names" #[name]>`) Vue помечает
  как зависящие от области видимости и заставляет перерисовываться всё поддерево при любом
  изменении (vuejs/core #5579, флаги `SlotFlags` в `componentSlots.ts`); в умной форме из-за
  этого `TransitionGroup` соседней секции играл лишний переход (2026-10-19). Объект слотов идёт
  явным пропом (`useSlots()` возвращает один и тот же объект, поэтому дети не перерисовываются),
  а часть рисует нужный слот как компонент: `<component :is="fieldSlot" v-bind="scope" />` — так
  же `BodyCell` PrimeVue рисует `column.children.body`, а Vuetify передаёт `slots` в строки
  таблицы. Если слоты нужны только одному компоненту, он рисует их сам через `<slot :name>`, как
  `Table.vue` в Nuxt UI. Компонентов-провайдеров, которые
  только делают `provide` и рисуют `<slot />`, нет и в тестах: конфиг даёт `global.plugins`
  (`createNuiConfig`), вложенный слой — вызов `provideNuiConfig` в скрипте самой фикстуры.
  Исключение одно: обход документа по спецификациям `render` схемы (`ContentNodes` в
  `@numior/content`), где теги и вложенность приходят из данных и компонент на каждый элемент
  недопустим. ESLint запрещает импорт `h`, `defineComponent`, `createVNode`, `renderSlot`,
  `FunctionalComponent` и соседних API из `vue` везде, кроме этого файла. Правило записано
  2026-10-19 после того, как `NuiFieldFrame`, `CellContent` таблицы, переключатель контента,
  фабрика `contentEmbedView`, `SmartSlot` умной формы, два примера доков и хосты тестов
  оказались на `h`.
- В каждом SFC порядок блоков: сначала `<template>`, затем `<script setup lang="ts">`,
  затем `<style>` (если он вообще нужен); линтер проверяет это правилом `vue/block-order`.
  Props объявляются `defineProps<Props>()` с reactive
  destructure для дефолтов: `const { size = 'md', disabled = undefined } = defineProps<Props>()`.
  Интерфейс props лежит в `<name>.types.ts`, необязательные поля объявлены с `| undefined`.
  Boolean, который должен наследоваться из контекста поля, получает дефолт `= undefined`
  (тристейт). Тип свойства не смешивает `boolean`, `false` или функцию с типом, который
  компилятор SFC не разбирает (константа-перечисление `(typeof X)[keyof typeof X]`, алиасы
  иконок): в собранном пакете у такого свойства остаётся только `Boolean` или `Function`, и
  приложение в режиме разработки предупреждает на его допустимых значениях. Перечисление,
  которое стоит рядом с `boolean` или `false`, объявляет тип явным объединением литералов, а
  константа сверяется с ним через `satisfies` (`NuiTreeSelectable`, `NuiSmartFormInline`): такой
  тип компилятор разбирает, и «выключено» остаётся `false`. Проверка в `test:artifacts`
  (2026-11-14). `withDefaults`, runtime-объекты props и `PropType` запрещены. v-model только
  через `defineModel`. Композаблы получают destructured props через getter:
  `useFieldControl(() => ({ id, disabled, required, invalid, label, description, error }))`;
  корень контрола оборачивается в `NuiFieldFrame v-bind="fieldFrame"`, так что `label`,
  `description` и `error` рисуются самим контролом, а `NuiField` нужен только для слотов и
  нескольких контролов в одном поле. Контрол, который держит
  неподтверждённый ввод (lazy-текст, число до blur, свой текст комбобокса, незажатое время),
  передаёт его коммит вторым аргументом: `useFieldControl(props, { commit: () => commitDraft() })`;
  поле формы вызывает эти коммиты перед программной отправкой.
- Функции — только стрелочные константы (`const sync = (): void => {...}`, `export const
  useX = () => {...}`); объявление `function` допустимо лишь там, где нужен собственный
  `this` (method shorthand в объектах, стабы прототипов). Хелперы без замыкания живут на
  уровне модуля, вложенные объявления функций внутри функций не пишутся; замыкания над
  состоянием композабла — минимальные стрелочные константы. Любой блок `if`/`else`/`for`/
  `while` заключён в `{}`. Линтер держит это правилами `func-style: expression`,
  `curly: all`, `prefer-arrow-callback`. Многострочные объявления, вызовы, импорты и экспорты
  отделяются пустыми строками (`@stylistic/padding-line-between-statements`,
  `lines-between-class-members` в ESLint): `<script setup>` читается как логические секции —
  пропы и модели, состояние, производные, обработчики, жизненный цикл, — а не как сплошной
  поток в духе Options API.
- Ранний выход вместо обёртки: если функция или тело цикла заканчивается блоком `if` без `else`,
  условие переворачивается в `if (...) { return; }` (в цикле — `continue`), а действия идут
  следом без вложенности. Порога нет: одно завёрнутое действие тоже выносится (решение
  пользователя 2026-11-11; до него правило пропускало блоки с одним действием и циклы).
  Функция с возвратом значения переворачивается, когда завёрнутый блок из двух и более действий
  кончается выходом, а за ним стоит один `return` с простым значением (`undefined`, литерал,
  имя, пустой список). Не трогаются: блок, который сам кончается `throw` или `break` (это уже
  выход), функция, где значение возвращают раньше хвоста, и блок с именем, занятым во внешней
  области (без автоисправления). `else` после `return` запрещён (`no-else-return`). Составное
  условие, которое после переворота читается хуже, получает имя
  (`const blocked = loading || (disabled && isLink.value)`). Держит правило ESLint
  `numior/guard-first` с автоисправлением (`scripts/eslint/guard-first.mjs`): отрицание
  сохраняет скобки операндов сравнения, а `a > b` становится `a <= b` — у величин, которые
  могут быть `NaN`, условие пишется руками.
- Список не разворачивается в аргументы вызова: `list.push(...found)`, `Math.max(...values)`,
  `splice(at, 0, ...items)`, `String.fromCharCode(...bytes)` кладут каждый элемент на стек и
  падают с `RangeError` около 125 000 элементов — а длину задают данные пользователя (точки
  графика, строки вставки, диапазон формулы). Добавление — цикл `for…of` с `push`, крайние
  значения — `min`, `max`, `minBy`, `maxBy` из `lodash-es`, замена содержимого — новый массив.
  Держит правило ESLint `numior/spread-arguments` (`scripts/eslint/spread-arguments.mjs`) для
  `packages/*/src` и `packages/*/server`; исключение — кусок фиксированного размера
  (`...bytes.subarray(at, at + SIZE)`).
- Приведения типов `as` и постфиксный `!` запрещены во всём репозитории, включая тесты и
  конфиги; единственное исключение — `as const`. Нужен тип — generic, type guard,
  `useTemplateRef<HTMLInputElement>()`, `wrapper.find<HTMLInputElement>()`, дискриминированное
  объединение вместо «пустого» значения.
- Типы не держатся «на доверии»: если тип значения нельзя доказать, меняется API, а не
  добавляется непроверенное чтение. Поле формы связывается селектором
  (`:name="(v) => v.contacts[i]?.name"`): путь записывает прокси, каждое чтение сверяется с
  селектором; строковый путь даёт `unknown`.
- Состояние из нескольких связанных флагов или «плана» (`focusPlan`, `dragging` + `source` +
  `target`) — размеченное объединение `{ kind: … }`: его забирают и очищают одним шагом
  (`createIntent().take()`), разбирают `switch` по `kind`, недостижимых сочетаний флагов нет.
- Модуль, в котором только типы, называется `<name>.types.ts`.
- Горячие пути (ввод, рендер строк, перетаскивание, валидация на каждое изменение) не
  сканируют коллекции повторно: индекс по ключу строится один раз на изменение источника,
  производные значения сохраняют идентичность, пока содержимое то же, дорогие объекты
  (`Intl.Collator`, форматтеры) кешируются.
- CSS по BEM: блок `nui-<name>`, элементы `nui-<name>__<part>`, модификаторы
  `nui-<name>--<key>-<value>` для перечислений (`--variant-soft`, `--tone-error`, `--size-sm`)
  и `nui-<name>--<state>` для состояний (`--checked`, `--invalid`, `--disabled`, `--loading`).
  Изменяемые значения вынесены в приватные custom properties (`--_tone`, `--_height`), которые
  задают модификаторы, а остальные правила только читают. `data-*` для вариантов и состояний
  не используются; состояние нативного контрола в CSS берётся из псевдоклассов
  (`:checked`, `:indeterminate`, `:disabled`, `:focus-visible`).
- Никаких атрибутных костылей (решение владельца 2026-11-13): ни `data-*` на элементах, ни
  селекторов `[data-…]` в CSS кита, документации и песочницы. Варианты, состояния, тема,
  цветовая схема, акцент и плотность — классы. Области не переобъявляют ключи темы: ни списков
  `--x: --theme(--x inline)`, ни одинаковых правил на `:root` и на селекторе области ради
  пересчёта. Тёмной или светлой области хватает `color-scheme`: значения на `light-dark()` и
  выведенные из них разрешаются по месту использования. Производный ключ (значение ссылается на
  другой ключ) объявляется в `@theme inline` и читается через `--theme()` или утилиту, не через
  `var()`, — тогда он считается на том элементе, где используется, и сам следует вложенному
  акценту, плотности и поверхности. Причина: 134 строки повтора ключей на `[data-nui-theme]` в
  переносе на Tailwind 4 — ручной дубль темы, который молча ломается, когда ключ забыли.
  Проверка — `pnpm check:styles` (вводится вместе с переделкой темы).
- Компонент другого пакета не перестилизуется снаружи (2026-11-05): стили пакета не делают
  субъектом селектора блок, часть или модификатор компонента чужого пакета (чужой блок можно
  читать как контекст — предок, `:has()`), а шаблон не вешает на чужой компонент свой класс, у
  которого есть CSS. Шаблон пакета не берёт и класс блока чужого пакета на свой элемент (2026-11-15:
  `NuiTableFilter` рисовал слой классом `nui-popover`): вид чужого компонента дают сам компонент
  (`NuiPopover` с `anchor`) и своя обёртка внутри него. Размер и цвет иконки задают `font-size` и `color` своей обёртки, поворот —
  проп `transform` или своя обёртка, отступы и ширину — своя обёртка, поведение — проп кита
  (`grip` у `NuiButton`, `maxHeight` у `NuiEditor`). Приложения-потребители (песочница, доки)
  могут размещать корень чужого компонента (ширина, отступы, flex — как классы Tailwind в
  примерах), но не трогают его части и модификаторы. Исключение одно: `@numior/editor-vue`
  разделяет блок `nui-content` с `@numior/content`, потому что вид редактора сам строит DOM
  блоков по схеме контента, а стили документа общие по `editor.adr.md`. Внутри `@numior/vue`
  компоненты кита собираются друг из друга, и проверка эту композицию не трогает. Проверяет
  `pnpm check:styles` (`scripts/check-kit-styles.mjs`) в составе `pnpm check`.
- Всё, что реагирует на клик, показывает `cursor: pointer`: кнопки, ссылки, опции, пункты меню и
  дерева, шевроны, значения барабанов; отключённое — `not-allowed`, ручки перетаскивания —
  `grab`/`grabbing` (у `NuiButton` — проп `grip`), ручки ширины — `col-resize`. Нативные для десктопа `default` у меню и
  списков не используются; e2e проверяет курсор у всех включённых контролов playground.
- Отключённое поле не рисует текстовую каретку: `.nui-field--disabled` задаёт
  `caret-color: transparent`, значение наследует нативный контрол. Chrome после щелчка по
  отключённому `<input>` отдаёт фокус ближайшему фокусируемому предку (панель вкладки, диалог,
  ячейка) и рисует мигающую каретку внутри поля, хотя ввод невозможен.
- Перетаскивание начинается только с ручки, никогда со всей строки или ячейки: иначе оно
  спорит с кликом (сортировка, выбор) и выделением текста.
- Появление со сдвигом начинается со стороны начала блока (`translate: 0 calc(var(--nui-space-1)
  * -1)`) или с `scale` меньше 1, но никогда снизу: сдвинутый за нижний край контейнера с
  `overflow: auto` блок входит в его прокручиваемое переполнение, и полоса прокрутки мигает всё
  время анимации (так мигало пустое состояние таблицы). Горизонтальные слайды укладываются в
  внутренний отступ своего контейнера прокрутки.
- Призрак перетаскивания не накрывает линию вставки: он занимает только часть поперёк оси
  движения (колонка — полосу заголовка, строка — компактную плашку у начала строки), а линия
  идёт через всю ширину или высоту и видна рядом с ним. Ручка призрака остаётся под указателем.
- Размеры считаются по border-box, и кит объявляет это сам: корень каждого блока и каждый
  элемент с паддингом или рамкой пишут `box-sizing: border-box`. Глобальный ресет страницы
  (`* { box-sizing }`, preflight Tailwind) не нужен и в playground отсутствует, чтобы e2e и
  скриншоты видели кит так же, как приложение без ресета.
- Движение обязательно: каждое изменение состояния имеет `transition` или `animation`
  через `--nui-duration-*` и `--nui-easing`. При `prefers-reduced-motion: reduce` токены
  обнуляют длительности; бесконечные анимации (спиннер) замедляются, но не исчезают.
  Каждая бесконечная анимация читает `animation-play-state: var(--nui-animation-play-state,
  running)`, чтобы приложение могло остановить её своей обёрткой (песочница так гасит демо вне
  экрана: их кадры отнимали около 6 мс у каждого кадра страницы). Токен не объявлен в теме
  специально: вложенный `[data-nui-theme]` сбрасывал бы `paused` предка обратно в `running`.
  Проверка — `pnpm check:styles`.
- Бесконечная анимация меняет только `transform`, `translate`, `rotate`, `scale` и `opacity`
  либо идёт шагами (`steps()`, `step-end`): такие ведёт композитор. Любое другое свойство
  (`background-position`, `inset-*`, размеры) требует кадра главного потока на каждый vsync —
  стиль, отрисовка и коммит 120 раз в секунду, пока анимация на экране, и лишний кадр задержки
  у любой прокрутки рядом (замер 2026-11-11: блок прокрутки возле скелетона 49 → 32 мс).
  Движущуюся часть несёт псевдоэлемент или дочерний элемент шире родителя на длину хода, родитель
  обрезает его (`overflow: hidden`); направление хода в RTL задаёт приватная переменная (`--_flow`),
  а не логическое свойство в кадрах. Проверка — `pnpm check:styles` и сценарий «без кадров главного
  потока» в `feedback.spec.ts`.
- Наведение и нажатие одинаковы во всём ките (2026-11-16, решение владельца после сравнения
  вариантов на живых кнопках; сверка с Vuetify, Material 3, shadcn, Radix и Fluent). Заливка
  подмешивает цвет своей подписи: `color-mix(in oklab, <заливка>, <подпись>
  var(--nui-state-hover))`, при нажатии — `var(--nui-state-pressed)`. Пара одна на весь кит,
  8 % и 16 %; токенов `-subtle`, `-tint` и `-overlay` больше нет. Сплошная кнопка и выбранный
  день берут тон и его `-foreground`; мягкий фон (мягкая кнопка, выбранный пункт, текущая
  страница, середина диапазона, сегмент) — `-soft` и `-soft-foreground`; выбранная строка
  таблицы — `-soft` и текст. Прозрачный пункт (меню, список, день календаря, страница, шаг,
  кнопки в шапке таблицы) получает `--nui-hover`/`--nui-pressed` — те же доли текста поверх
  прозрачного, поэтому он работает на любом слое и полосе; непрозрачная карточка или строка
  смешивает ту же долю текста со своей поверхностью; ghost- и outline-кнопки и пункт с тоном
  ошибки кладут ту же долю цвета подписи поверх прозрачного. Направление задаёт подпись, а не
  схема: заливка со светлой подписью светлеет, с тёмной — темнеет. Сдвиг светлоты
  (`oklab(from … calc(l ± …))`) в состояниях запрещён, проверка — `pnpm check:styles`: на
  насыщенных тонах он выходил из sRGB и уводил оттенок (оранжевый краснел), гасил кнопку в
  тёмной схеме и не был виден на чёрной заливке. Одна сила для кнопок и строк — выбор
  владельца: строка на 8 % отзывается сильнее, чем у Radix и shadcn (шаг светлоты около 0,06
  против 0,03–0,04). Контраст подписи держит AA в покое и при наведении; при нажатии он может
  опуститься ниже (нажатая сплошная primary сайта — 3,9). Переход цвета при наведении —
  `--nui-duration-fast` с `--nui-easing`, нажатие включается сразу
  (`--nui-duration-instant`); `normal` и `slow` остаются сменам состояния (включение, шаг,
  появление слоя). Выбранное под курсором остаётся в своём тоне и подмешивает свою подпись:
  правило простого наведения не должно перебивать выбранное по специфичности (2026-11-12:
  текущая страница пагинации становилась серой, выбранные строка таблицы и день календаря не
  отзывались). Простое наведение нейтральное: акцент означает только выбор (решение
  владельца 2026-11-12). Исключение из перехода при наведении — строки прокручиваемых наборов
  (2026-11-11): строка таблицы, строка `NuiList` и `NuiTree` и пункт выпадающего списка на
  классе `nui-list-item` меняют фон без перехода, потому что при прокрутке под неподвижным
  указателем строки сменяются каждый кадр, и переход фона в главном потоке добавлял два кадра к
  каждому шагу колеса (замеры в `table.adr.md`, «Прокрутка в композиторе и фон строки без
  перехода», и в `data-display.adr.md`, «Фон строки списка и дерева без перехода»). Цвет текста
  выбранной строки по-прежнему переходит за `--nui-duration-fast`.
- Мелкий текст в строке с выравниванием по базовой линии (`align-items: baseline`) объявляет свой
  `line-height: var(--nui-line-height-control)`. Унаследованный бокс строки соседа (длина, а не
  множитель) у текста меньшего кегля стоит ниже и растягивает строку на пиксель: метка
  «Изменено» у имени файла листа сдвигала весь лист после первой правки, сводка шагов на узком
  экране была 21 px вместо 20 (2026-11-11).
- Область прокрутки с большим содержимым несёт непрозрачный фон своей поверхности: без него
  Chromium на DPR ниже 1,5 прокручивает её главным потоком с перерисовкой, а не в композиторе.
- Соседние липкие элементы над прокручиваемым содержимым — отдельные слои: на дробном масштабе
  в шве между ними видно содержимое под ними. Под швом лежит подложка в слое того элемента, что
  рисуется раньше: она начинается внутри своего элемента (не от его края — иначе тот же шов
  остаётся между элементом и его подложкой) и выступает под соседа на 4 px. Проверка —
  сравнение снимков со скрытым и с залитым содержимым на масштабах 0,9–1,75, включая 1,1 и 1,33.
- Движение идёт через `transform`/`translate`/`scale`, а не через размеры и смещения:
  ползунок переключателя, заливка линии степпера, подсказка графика. Исключения записаны:
  индикатор вкладок (слой композитора под текстом даёт дрожание текста), ширина сайдбара,
  раскрытие через `grid-template-rows`, ручки таблицы в потоке, высота задних тостов стопки
  (scale исказил бы рамку и скругление) и заливка нативного `<progress>`. Поверхность с
  текстом (диалог, панель, карточка) не масштабируется при появлении: после перехода `scale`
  Chromium оставляет текст в растре анимации, и при первой перерисовке (наведение на кнопку)
  весь текст сдвигается на долю пикселя; появление — `opacity` и `translate`. Замер 2026-11-06
  (Chromium, ЦП замедлен в 4 раза, 8 повторов, A/B/A): щелчок по переключателю даёт 1,8
  раскладки вместо 12,6 (1,6–1,8 мс вместо 7,7), переход подсказки графика между точками —
  1,8 вместо 10,1 (2,0–2,9 мс вместо 7,0); самый длинный кадр действия не изменился.
- Части одного элемента меняют цвет вместе. Переход объявляет тот элемент, у которого цвет
  задан: контейнер для наследующего текста и каждая часть со своим цветом (иконка, описание)
  с тем же токеном. Приватная переменная цвета переключается мгновенно, поэтому часть без
  своего перехода обгоняет текст. Состояние задаёт цвет части явным значением, а не
  `currentColor`: наследуемый цвет уже анимируется, и второй переход поверх него отстаёт.
  Потомок, который цвет наследует, свой переход цвета не объявляет.
- Иконки кита — алиасы из `iconAliases` (primitives: алиас → имя файла Lucide, тип
  `IconAlias` — ключи карты). `NuiIcon` и `useIcon` берут переопределение из конфигурации, а
  без него грузят иконку `@lucide/vue` по ключу через `import.meta.glob`, ограниченный файлами
  кита (`icon/kit-icons.ts`), и кешируют компонент: каждая иконка — отдельный чанк около 180 байт
  gzip, загружается только запрошенная. Glob по всем ~1860 файлам запрещён: его карта
  загрузчиков весит 62 КБ gzip и грузится сразу; `import('@lucide/vue').then((icons) =>
  icons[name])` тянет весь набор (169 КБ gzip). Пакеты и приложения передают свои иконки
  компонентом (`import { Bold } from '@lucide/vue'`, `:icon="Bold"`), без своих алиасов и без
  `declare module`. Иконки Lucide в `dist` кита идут с `LICENSE-lucide-vue`. Иконка, смонтированная
  до загрузки своего файла, проявляется один раз: состояние `nui-icon--appearing` снимается по концу
  анимации. Иначе оно остаётся на элементе, и анимация повторяется при каждой смене или новом показе
  глифа — в строках виртуального списка на каждом шаге прокрутки.
- Кнопка в `loading` сохраняет ширину и фокус: содержимое остаётся в потоке с `opacity: 0`,
  спиннер абсолютно позиционирован по центру, вместо `disabled` ставится `aria-disabled`, а
  клик отменяется.
- Проп с типом `Function | false` или иным объединением с `boolean` получает
  destructure-дефолт `= undefined`, как тристейт-булево: иначе Vue приводит отсутствующий
  проп к `false`.
- Иконка кнопки задаётся пропом `icon` (алиас реестра перед текстом); слот с `NuiIcon`
  остаётся для особых случаев. Кнопка только с иконкой квадратная: `NuiButton` сам
  распознаёт `icon` без текста или слот из одних `NuiIcon` (модификатор `icon-only`, проп
  `iconOnly` переопределяет) и требует `aria-label`; прямоугольная кнопка с одной иконкой не
  допускается.
- Комментарии в коде (TS, Vue, CSS, конфиги) не пишутся; объяснения живут в `apps/docs`
  и Archcore. Имена несут смысл.
- Каждый новый компонент, композабл и токен выходит вместе с документацией: примеры RU/EN
  в `apps/docs/examples`, описания в `apps/docs/api/<семейство>.ts`, страница RU/EN по шаблону
  `docs-writing.rule.md`, пункт сайдбара в `config.ts`; композабл — страница в разделе
  «Композаблы» с `<SignatureReference>`. `pnpm docs:check` падает на компоненте без описаний и
  на композабле без сигнатуры, исключений нет.
- Тексты интерфейса (имена кнопок, пустые состояния, объявления, ошибки) живут в каталоге
  `<comp>.messages.ts` (`NuiMessageCatalog` с `en` и `ru`), зарегистрированном в
  `NuiVueMessages`. Текстовые пропы (`label`, `*Label`, `announce`) дефолта не имеют: компонент
  берёт `prop ?? messages.value.key` из `useMessages(catalog, locale?)`, компонент с пропом
  `locale` передаёт его в `useMessages`. Тексты с параметрами — функции одного объекта,
  множественное число — `plural`. Решение — `messages.adr.md`.
- Фокус и измерения внутри поповера выполняются, когда браузер его уже показал. Поповер,
  открытый нативным invoker (`popovertarget`: щелчок, Enter, пробел), сообщает об открытии в
  `beforetoggle`, flush Vue проходит до показа, и `focus()` на скрытом содержимом молча не
  срабатывает. Поэтому вход в поповер идёт через `useShownPopover(open, settle)`
  (`packages/vue/src/shared/use-shown-popover.ts`): `settle` пробуется в post-flush (путь
  `show()` из кода) и повторяется на нативном `toggle`, пока не вернёт `true`; `takeFocus`
  отвечает, перешёл ли фокус. jsdom разницы не видит, поэтому открытие щелчком, Enter и
  пробелом с проверкой фокуса и следующей стрелки проверяется в e2e (`navigation.spec.ts`,
  `pickers.spec.ts`).
- Жест, который на своё время вешает слушатели на `window` или `document` (перетаскивание,
  изменение размера, ожидание отпускания кнопки), заканчивается вместе с владельцем: функция
  завершения жеста зарегистрирована в `onScopeDispose`. Компонент, размонтированный посреди
  жеста, не оставляет слушателей, таймеров и отложенных действий. Проверка — правило ESLint
  `numior/page-listeners` (`scripts/eslint/page-listeners.mjs`) для `packages/*/src`: файл с
  `window|document|globalThis.addEventListener` обязан вызывать `onScopeDispose`,
  `tryOnScopeDispose`, `onBeforeUnmount` или `onUnmounted`. Отложенный показ меню после
  отпускания кнопки — композабл `useAfterRelease()` из `@numior/primitives`.
- Одно действие — один рендер. Watcher с `flush: 'post'` только трогает DOM: вызывает
  `focus()`, `showPopover()`, измеряет и пишет `element.style` или custom properties; он не
  пишет в реактивное состояние и не запускает второй рендер. Кто активен, где tab stop и
  куда пойдёт фокус, решается до рендера — в обработчике действия или в watcher без
  `flush` (`pre`), а id опций индексные (`optionElementId(listId, index)`), поэтому активную
  опцию можно назначить строкой ещё до того, как она отрисована (`setActive(id)` в
  `useListNavigation`). Результаты измерений (позиция и сторона плавающего элемента,
  ширины колонок и sticky-смещения таблицы, индикатор табов) живут в обычных переменных и
  пишутся прямо в DOM; в реактивном состоянии остаются только пользовательские значения
  (ширины после resize, порядок, закрепления). Осознанное исключение — `useVirtualList`:
  окно строк по природе состояние, но оно меняется от события скролла, а не из watcher.
  Окно виртуализации — липкий блок строк между двумя спейсерами скроллера (список дерева,
  `<table>` таблицы): композитор прокручивает его сам и держит у края, когда ползунок убегает
  дальше отрисованных строк. Размеры спейсеров и границы липкости отдаёт `useVirtualFrame`
  зарегистрированными ненаследуемыми переменными `--_window-*`, растущий спейсер пишется в
  DOM до рендера, строки ключуются слотом `items[].slot`, а цель для одного
  сдвига окна в prod-сборке — 4 ms главного потока (скрипт + стили + раскладка + paint по
  трассировке Chromium, `tests/bench`). Пороги p95 в `bench/thresholds.json` пакетов держат
  достигнутый уровень (2026-09-30: дерево 6 ms, таблица 22 ms при факте 5.1 и 19 ms), их
  снижают вместе с работой над путём рендера ячеек, а не поднимают.
  Строки и ячейки, которые входят в окно при прокрутке, не несут своих слушателей `pointer*`,
  `touch*` и `wheel`: в WebKit каждый такой `addEventListener` (на любом элементе, даже не
  вставленном, и на `window`) пересчитывает стили всего документа, 300–800 мс на странице
  песочницы (2026-11-13). Нажатия на части строк ловит один слушатель стабильного предка,
  поставленный при монтировании (`createPressTargets`, реестр ручек таблицы `table-handles.ts`),
  а переменные, которые окно пишет на каждом сдвиге, его дети сбрасывают в `initial`. То же для
  всего, что появляется по действию человека: протяжка и удержание идут через
  `usePointerSession`, а не через `addEventListener` на `window` в начале нажатия, слушатель не
  включается и не выключается состоянием (ESLint `numior/pointer-listeners`, раздел «Слушатели
  нажатий» в @.archcore/component-conventions.adr.md).
  Текст на рисунке — HTML поверх SVG, не `<text>`/`<tspan>`/`<textPath>`: пока на странице есть
  разложенный SVG-текст, WebKit пересчитывает стили всего документа на каждый показ поповера и
  каждую смену слушателей указателя (ESLint `vue/no-restricted-syntax`, `SVG_TEXT`; образец —
  слой `nui-chart__labels`).
  Сторона плавающего элемента приходит в CSS числовыми переменными `--_side-x`/`--_side-y`
  (вектор от опоры к элементу), а не классами-модификаторами.
- Направление письма читается через `useDirection(anchor)` (конфиг → ближайший `dir` →
  `document`), а не через `closest('[dir]')` в компоненте.
- Раскладка: `packages/vue/src/<name>/{Nui<Name>.vue,<name>.types.ts,<name>.css}`;
  `src/styles.css` — манифест `@import`, сборка эмитит `dist/styles.css` и
  `dist/styles/<name>.css`. Каждый CSS-файл компонента самодостаточен.

Тесты:

- Unit-тесты лежат в `packages/<pkg>/test/`. Компоненты тестируются через драйверы
  (`test/drivers/<name>.ts`), композаблы — через харнессы (`test/harness`). Спека читается как
  сценарий: только вызовы драйвера и `expect`, без разбора DOM, `as` и одноразовых хелперов.
- Фабрики драйверов синхронные; ожидание асинхронных частей — `await driver.ready()`.
- Одно действие драйвера ждёт ровно один `await nextTick()`. Два тика подряд означают
  цепочку рендеров в компоненте, которую нужно убрать, а не спрятать в хелпер;
  `scripts/check-tests.mjs` (`pnpm test:ticks`) падает на таком паттерне.
- E2E: page objects в `tests/e2e/pages`; спеки не обращаются к `page` напрямую: `keyboard`,
  `mouse`, `touchscreen`, `evaluate`, `locator`, `getBy*`, `waitForTimeout`, `frameLocator` и
  `$` у `page` и `<x>.page` отклоняет `no-restricted-syntax` в ESLint для `tests/e2e/**/*.spec.ts`.
  Методы page object названы по действию пользователя или по тому, что читает тест
  (`closeMenu`, `jumpToDataEdge('down')`), а не пересылают произвольную клавишу. Фиксированная
  пауза — только именованный шаг page object там, где пауза и есть сценарий (задержка под
  курсором); иначе ждут через `expect.poll`, `toBeVisible` или хелперы `settled`.
- Тайпгарды во всех наборах тестов берутся из `packages/primitives/test/support/guards.ts`
  (базовые проверки и комбинаторы `nullable`, `optional`, `listOf`, `recordOf`, `oneOf`,
  `anyOf`, `shapeOf`, `parseAs`); тип вывода выводится из гарда (`Guarded<typeof guard>`), а
  гард утверждает только то, что проверил: проверка наличия ключей не выдаётся за полный тип.
- Каждый компонент проходит четыре уровня: unit-контракт, SSR-рендер (`renderMarkup`,
  детерминированная разметка, id на сервере), e2e-сценарий в playground и axe в light/dark
  под `reducedMotion: 'reduce'`.

## Rationale

Правила зафиксированы после ревью первой волны компонентов 2026-09-22: runtime-объекты
props и `withDefaults` дублировали типы, `data-*` дублировали классы, `as` прятал ошибки
типов, а спеки с ручным разбором DOM не читались. Правило «одно действие — один рендер»
добавлено 2026-09-25: post-flush watcher'ы, которые писали в `activeId`, `pending` или в
измеренные размеры, запускали второй рендер, и драйверы ждали два `nextTick()` подряд. Единый стиль ускоряет ревью и делает
поведение предсказуемым для CLI-копирования визуальных компонентов.

## Examples

Good: `const { size = 'md', disabled = undefined } = defineProps<NuiInputProps>()`;
`:class="[`nui-input--size-${size}`, { 'nui-input--invalid': isInvalid }]"`;
`const input = InputDriver.mount({ modifiers: { lazy: true } }); await input.type('a')`;
`useTemplateRef<HTMLInputElement>('input')` вместо `event.target as HTMLInputElement`.

Bad: `function sync(next) {...}` внутри композабла и `if (!el) return;` без скобок;
`withDefaults(defineProps<Props>(), {...})`; `defineProps({ size: { type: String as PropType<Size> } })`;
`:data-variant="variant"`; `(wrapper.element as HTMLInputElement).value`;
алиас пакета через `declare module '@numior/primitives'`; комментарий с объяснением «почему» в SFC.

## Enforcement

Самопроверка по этому документу перед передачей изменений; `pnpm check` (Fallow ловит
неиспользуемые члены драйверов и дубли, `pnpm test:ticks` — двойные `nextTick()` в тестах,
ESLint — текстовые пропы с дефолтом и тексты вне каталогов, `check-artifacts` — tree-shaking
каталогов, `pnpm check:styles` — стили компонентов чужого пакета снаружи);
ревью пользователя. Практические шаблоны — в
скиллах `.claude/skills/nui-component` и `.claude/skills/nui-testing`, краткая версия —
в `AGENTS.md`.
